# mml-fm-audio 仕様書（v0.6 / 2026-10-25）

## 0. 概要

### 位置づけ
個人開発ゲーム（ankardo の各種ブラウザゲーム）で使う、**軽量楽曲フォーマットと再生ライブラリ**。

### 目標
- 着メロ時代（2000年代前半、ヤマハ MA-2/MA-3 や YMF825 など）の FM 音源相当の音質で、ブラウザ上で BGM と効果音を鳴らす。
- 楽曲はテキスト（MML 風）で保持し、軽量に配布する。

### 非目標
- 実機の完全再現（サイクル精度のエミュレーション）。
- SMAF（.mmf）の再生。
- 既存ファームウェア・ミドルウェアの移植。

### 方針
- 実装は TypeScript のみで始める。WASM は負荷の実測で必要と判断した場合のみ検討する。
- 本書で「暫定」とした値は、実装・試聴の結果で変更してよい。
- 「要確認」とした項目は、実装前に一次資料で確認する。

---

## 1. 全体構成

```
mml-fm-audio/
├─ packages/
│  ├─ engine/      音源（AudioWorkletProcessor：FM、ノイズ、ミキサー、出力処理）
│  ├─ sequencer/   MML パーサとシーケンサ（ティック管理、イベント発行）
│  ├─ runtime/     ゲーム向け API（FmAudio）
│  └─ conv/        SMF → MML 変換 CLI（Node.js）
├─ voices/         音色定義（JSON）と出典・ライセンス表記
├─ demo/           試聴ページ（MML 貼り付けで再生、音色の鍵盤試奏）
└─ docs/           本仕様書、MML 文法、音色形式、API リファレンス
```

### 依存方向
`runtime → sequencer → engine`。`conv` は `sequencer` の MML パーサを、往復検証用に参照してよい。

### データの流れ
1. DAW → SMF → `conv` → MML テキスト。Claude などが MML を直接書く経路もある。
2. `runtime.load` → `sequencer` で解析・タイミング管理。
3. AudioWorklet 上の `engine` に発音イベントを送る。

## 2. 音源エンジン（packages/engine）

### 2.1 基本仕様

| 項目 | 仕様 |
|---|---|
| 合成方式 | FM（位相変調）。1 音色あたり 2 または 4 オペレーター |
| 同時発音数 | **BGM 16 音と効果音 4 音**（別々のボイス。効果音は BGM のボイスを借りない）。負荷の実測後に見直す |
| アルゴリズム | 8 種（2 オペレーター用 2 種 + 4 オペレーター用 6 種。結線は §3.6） |
| 波形 | 29 種（番号 0〜30 のうち 15、23 を除く。31 も空き） |
| エンベロープ | 整数段階で指定するレート方式（AR / DR / SR / RR：0〜15、SL：0〜15） |
| LFO | 1 系統。トレモロ（AM）とビブラート（VIB）をオペレーター単位で有効化 |
| ノイズ | ホワイトノイズ発生器（ドラム用）。音色ごとにエンベロープを持つ |
| 出力 | ステレオ。ボイスごとにパンを持つ |
| サンプリングレート | AudioContext の値（通常 44.1 / 48 kHz）で直接生成 |
| 量子化 | 最終出力を 16bit 相当に丸める（オン・オフ可。既定はオン） |
| スピーカー風フィルター | ハイパス（暫定 300 Hz）とローパス（暫定 7 kHz）。オン・オフ可。値は試聴で調整 |

### 2.2 実装上の注意
- エンベロープのレート表や波形表は**独自に設計**する。実機の内部テーブルを再現する必要はない。耳で着メロ相当に聞こえれば可。
- 発音していないボイス（エンベロープ終了済み）は計算しない。
- ボイスの奪い合い：BGM は 16 音、効果音は 4 音を超えたら、それぞれの中で最も古く発音したボイスを止めて新しい音に割り当てる。
- メインスレッドとの通信は `port.postMessage` を使い、イベントにはサンプル単位の時刻を付ける（ジッター対策）。
- 負荷計測用に、1 ブロックあたりの処理時間を集計してデモに表示できるようにする。

## 3. 音色定義（voices/）

### 3.1 方針
パラメーターの種類と値の範囲を **YMF825 の音色パラメーターに揃える**。目的は、ヤマハが MIT ライセンスで公開している YMF825 の音色データ（YMF825_sample の tonedata）を変換して、初期の音色集にすることである。

- 対外的に「YMF825 互換」とは表記しない。「YMF825 の音色データを読み込める」といった事実の説明にとどめる。
- パラメーター構成と値の範囲は、YMF825Board の IF 仕様書（YMF825_sample の manual と tonedata/sysexspec.md）で確認済み（2026-10-11）。

### 3.2 FM 音色（JSON）

```json
{
  "id": 0,
  "name": "Piano",
  "kind": "fm",
  "bo": 0,
  "alg": 4,
  "lfo": 0,
  "ops": [
    { "wave": 0, "mul": 1, "dt": 0, "tl": 20, "ar": 15, "dr": 4, "sl": 3, "sr": 2, "rr": 6,
      "ksl": 0, "ksr": 0, "fb": 3, "am": 0, "amDepth": 0, "vib": 0, "vibDepth": 0, "xof": 0 },
    { "...": "2 または 4 オペレーター分" }
  ]
}
```

| 項目 | 範囲 | 意味 |
|---|---|---|
| `id` | 0–127 または `null` | GM の楽器番号。割り当てない音色は `null` |
| `bo` | 0–3 | 基本オクターブ。0 を標準の高さとし、1〜3 は 1〜3 オクターブ下げる（IF 仕様書の比 ×2, ×1, ×1/2, ×1/4 を、0 を基準に置き直したもの） |
| `alg` | 0–7 | アルゴリズム番号。0–1 は 2 オペレーター、2–7 は 4 オペレーター。結線は §3.6 |
| `lfo` | 0–3 | LFO の速さ（1.8、4.0、5.9、7.0 Hz） |
| `wave` | 0–31 | 波形番号。15、23、31 は空きで、サインで代替し警告を出す |
| `mul` | 0–15 | 周波数倍率。0→1/2、1〜9→値のまま、10・11→10、12・13→12、14・15→15 |
| `dt` | 0–7 | デチューン（値は独自。暫定で 0, +3, +6, +9, 0, −3, −6, −9 cent） |
| `tl` | 0–63 | 出力レベル（大きいほど小さい。1 段 0.75 dB、暫定） |
| `ar` `dr` `sr` `rr` | 0–15 | アタック、ディケイ、サステイン中の減衰、リリースの各レート。SR=0 は音量を保つ |
| `sl` | 0–15 | サステインレベル（1 段 3 dB、暫定） |
| `ksl` | 0–3 | 高い音ほど音量を下げる量（0、3、1.5、6 dB/oct） |
| `ksr` | 0–1 | 高い音ほどエンベロープを速める |
| `fb` | 0–7 | 自己帰還量（0、π/16、π/8、π/4、π/2、π、2π、4π）。有効なのは op1 と、アルゴリズム 2・5 の op3 のみ |
| `am` / `amDepth` | 0–1 / 0–3 | トレモロの有効化と深さ（1.3、2.8、5.8、11.8 dB） |
| `vib` / `vibDepth` | 0–1 / 0–3 | ビブラートの有効化と深さ（3.4、6.7、13.5、26.8 cent） |
| `xof` | 0–1 | キーオフを無視して鳴らし続ける |

`ops` はアルゴリズムが使う数（2 または 4）以上を要し、余りは無視する。

### 3.3 番号の割り当て
- `@0`〜`@127`：GM の楽器番号に対応させる。SMF のプログラムチェンジはこの番号へそのまま変換する。
- `@128`〜：ドラム音色（§3.4）。

### 3.4 ドラム音色（JSON・暫定）
FM 音とノイズを重ねて作り、必要なら音程を急降下させる。

```json
{
  "id": 128,
  "name": "bd",
  "kind": "drum",
  "fm":    { "voice": { "...": "§3.2 と同じ FM 音色" }, "note": 36, "level": 1.0 },
  "pitch": { "fromSemitone": 24, "toSemitone": 0, "decayMs": 40 },
  "noise": { "level": 0.1, "ar": 15, "dr": 10, "sl": 15, "rr": 12, "color": "white",
             "repeat": { "count": 3, "intervalMs": 12 } }
}
```

| 項目 | 範囲・意味 |
|---|---|
| `id` | 128〜255 |
| `fm` | 省略可。`voice` は §3.2 の FM 音色、`note` は 0〜127（ドラムはこの高さで鳴る）、`level` は 0〜1 |
| `pitch` | 省略可（`fm` があるときのみ）。音程を `fromSemitone` から `toSemitone` 半音へ、`decayMs` を時定数として指数的に近づける。半音は −48〜48、`decayMs` は 0 より大きく 1000 以下 |
| `noise` | 省略可。`level` は 0〜1、`ar`・`dr`・`rr` は 1〜15、`sl` は 0〜15、`color` は `"white"` のみ。アタック → ディケイ（`sl` まで）→ その後は `rr` の速さで無音まで下がる |
| `noise.repeat` | 省略可。ノイズのエンベロープを `intervalMs`（1〜100）ごとに `count`（1〜8）回かけ直す（クラップ用） |

- `fm` と `noise` の少なくとも一方が要る。
- ドラムはキーオフを無視し、鳴り終わるまで鳴る。そのため鳴り終わらない音色は受け付けない：`fm.voice` の出力するオペレーター（§3.6）は `ar`・`dr` が 1 以上で、`sl` が 15 か `sr` が 1 以上でなければならない。

初期の 8 種（番号は 128〜135 の順）：

| 名前 | 楽器 | 構成の目安 |
|---|---|---|
| `bd` | バスドラム | サイン波 + 音程の急降下 |
| `sd` | スネア | ノイズ + 短い FM 音 |
| `ch` | クローズドハイハット | 非常に短いノイズ |
| `oh` | オープンハイハット | やや長いノイズ |
| `cy` | シンバル | 長いノイズ（+ 金属的な FM 音） |
| `lt` | ロータム | サイン波 + 音程の降下 |
| `ht` | ハイタム | サイン波 + 音程の降下（高め） |
| `cp` | クラップ | ノイズを短く数回重ねる |

### 3.5 出典とライセンス
- `voices/` に YMF825 の音色データ由来の音色を含める場合は、元データの出典（YMF825_sample, Copyright (c) 2017 Yamaha Corporation, MIT License）とライセンス全文を `voices/LICENSE-YMF825.txt` に収録する。
- 独自に作った音色と、YMF825 データ由来の音色は、ファイルを分けて管理する。

### 3.6 アルゴリズムの結線

`→` は左のオペレーターが右を変調すること、`+` は出力で加算することを表す。`(fb)` は帰還を持つ。

| alg | 結線 | 出力するオペレーター |
|---|---|---|
| 0 | 1(fb) → 2 | 2 |
| 1 | 1(fb) + 2 | 1, 2 |
| 2 | 1(fb) + 2 + 3(fb) + 4 | 1, 2, 3, 4 |
| 3 | (1(fb) + (2 → 3)) → 4 | 4 |
| 4 | 1(fb) → 2 → 3 → 4 | 4 |
| 5 | (1(fb) → 2) + (3(fb) → 4) | 2, 4 |
| 6 | 1(fb) + (2 → 3 → 4) | 1, 4 |
| 7 | 1(fb) + (2 → 3) + 4 | 1, 3, 4 |

2 オペレーターのアルゴリズム（0、1）では、op3・op4 は計算しない。音色 JSON の `ops` は 2 要素でも 4 要素でもよい。

## 4. MML 文法（packages/sequencer）

独自の最小方言とする。既存方言（PMD、MUCOM88 など）との互換性は持たない。詳しい文法は `docs/mml.md`。

### 4.1 全体
- 1 行が 1 トラックへの記述。行頭のトラック名に続けて命令を書く。同じトラック名の行は連結して解釈する。
- `;` から行末まではコメント。
- 内部の時間分解能は **四分音符 = 96 ティック**。32 分音符、3 連の 16 分音符・32 分音符を整数で表せる。

### 4.2 トラック名
| 名前 | 用途 |
|---|---|
| `A`〜`P` | メロディ用トラック（MIDI チャンネル 1〜16 に相当。ただしチャンネル 10 は使わない） |
| `A1`, `A2`, … | サブトラック。和音を音の高い順に分割したもの（主に変換ツールが生成） |
| `R` | ドラム専用トラック |
| `R1`, `R2`, … | ドラムのサブトラック。同時に打つドラムを分けたもの（主に変換ツールが生成）。`R` と同じ規則で解析する |

曲のトラックは 30 個まで（違うトラック名の数）。超えるとエラー。

`t`（テンポ）、`L`（ループ開始）、`E`（ループ終了）は全体に作用する。慣例として `A` トラックに書く。

### 4.3 命令

| 命令 | 意味 | 例 |
|---|---|---|
| `c d e f g a b` | 音符。直後に `+`（シャープ）または `-`（フラット）、音長、`.`（付点）を付けられる | `c+8.` |
| `r` | 休符 | `r4` |
| `oN` | オクターブ指定（0〜8、既定 4） | `o5` |
| `<` `>` | 1 オクターブ下げる・上げる | `>c` |
| `lN` | 既定の音長（1, 2, 4, 8, 16, 32、3 連の 3, 6, 12, 24, 48） | `l8` |
| `&` | タイ（前の音と連結） | `c4&c16` |
| `%N` | 音長をティックで直接指定（変換ツール向け） | `c%36` |
| `tN` | テンポ（BPM、小数可） | `t132` |
| `@N` | 音色番号 | `@0` |
| `vN` | 音量（0〜15、既定 12）。持続中のノートにもその位置から効く（タイの間に書ける） | `v10` |
| `pN` | パン（0〜127、64 が中央） | `p32` |
| `qN` | ゲートタイム（1〜8、既定 8）。音長の N/8 のところでキーオフする | `q6` |
| `B±N` | ピッチベンド（セント単位、±1200。暫定）。持続中のノートにもその位置から効く（タイの間に書ける） | `B+50` |
| `[ ... ]N` | N 回繰り返し（入れ子可）。N は省けない | `[cdef]2` |
| `L` | ループ開始位置（ループ終了の位置まで来たらここへ戻る） | `L` |
| `E` | ループ終了位置（省けば曲の終わり） | `E` |

ループの中（`L` 以上、ループ終了未満）でノートオンしたノートの長さ（`q` を掛け、タイでつないだ全体）は、ループ 1 周の長さの 16 倍まで。超えるとエラー。同じノートが周ごとに重なるのを 16 周分までに抑え、再生時間に比例して溜まり続けないようにするための上限。`L` の前のノートと、`L` のない曲は対象外。`E` がない曲では、ノートが曲の終わり（ループ終了）を越えないので、この規則に当たらない。

### 4.4 ドラムトラック（R）
- 音符の代わりにドラム名（§3.4 の 2 文字）を書く。音長の指定方法は音符と同じ。
- 解析時は、ドラム名を 1 文字の命令より優先して照合する。例えば `lt` はロータムとして読む。
- `@` は使わない。`v` と `p` は使える。音符・`o < > & B` は使えない（`docs/mml.md` のドラムトラックの節を参照）。

```
A t132 L @0 v12 o4 l8 cdefgab>c
B @33 v11 o2 l4 c c g g
R v12 l8 [bd ch sd ch]2 bd bd sd cp
```

### 4.5 エラー処理
- 解析エラーは、行番号・列番号・理由を付けて報告する。
- エラーが 1 つでもあれば再生しない。ゲーム実行時も例外は投げず、警告を出す。

## 5. ゲーム向け API（packages/runtime）

### 5.1 API

詳しい引数・振る舞いは `docs/api.md`。

```ts
const audio = await FmAudio.init({ voices });      // AudioWorklet の読み込み、音色集の登録（voices は省略可）
await audio.resume();                              // ユーザー操作の後に呼ぶ（自動再生の制限への対応）

const song = audio.load(mmlText);                  // 解析済みの曲オブジェクトを返す。エラーは song.errors に入る
audio.playBgm(song);                               // BGM は同時に 1 曲。再生中なら差し替える。ループは MML の L で決まる
audio.stopBgm({ fadeMs: 500 });
audio.pauseBgm(); audio.resumeBgm();

audio.playSe(seSong);                              // 効果音。複数同時に鳴らせる
audio.setVolume({ master: 1.0, bgm: 0.8, se: 1.0 });
audio.setSpeakerFilter(true);
audio.on('loop' | 'end' | 'warning', handler);
```

### 5.2 効果音
効果音も MML で書く（短い曲として扱う）。例：`A t200 @80 o6 l32 c e g >c`

### 5.3 発音数の配分
効果音は BGM とは別の 4 ボイスで鳴らし、BGM のボイスを借りない。効果音どうしで 4 音を超えたら、効果音の 4 ボイスのうち最も古くノートオンした音のボイスを止めて使う（音単位）。

## 6. SMF → MML 変換（packages/conv）

### 6.1 形態
Node.js の CLI。

```
fm-conv song.mid -o song.mml [--quantize 32] [--report]
```

### 6.2 変換対象

| SMF のイベント | MML |
|---|---|
| ノートオン・オフ | 音符、休符 |
| テンポ | `t` |
| プログラムチェンジ | `@`（GM の楽器番号のまま） |
| CC7 × CC11 | `v`（掛け合わせて 0〜15 に丸める） |
| CC10 | `p` |
| ピッチベンド | `B`（ベンド幅は既定で ±2 半音とし、RPN 0 があれば反映） |
| マーカー `loop`（大文字・小文字を区別しない） | `L` |
| その他 | 捨てる。`--report` で捨てたイベントの種類と件数を表示する |

### 6.3 トラックの割り当て
- チャンネル 1〜16 を `A`〜`P` に割り当てる（チャンネル 10 を除く）。
- チャンネル 10 は `R` に割り当てる。
- サブトラックを含めて 30 個を超える場合の扱いは M5 で決める（sequencer は 30 個を超えるとエラーにする）。

### 6.4 和音
同じトラックで同時に鳴る音を、音の高い順に `A1`, `A2`, … へ分割する。和音が減った区間は休符で埋める。音色・音量・パンは全サブトラックに複製する。

### 6.5 量子化
- 既定は 32 分音符単位。3 連符は検出して 3 連の音長で表す。
- 量子化の単位は `--quantize` で変更できる。

### 6.6 ドラムの割り当て（GM のノート番号）

| ドラム名 | GM のノート番号 |
|---|---|
| `bd` | 35, 36 |
| `sd` | 38, 40 |
| `cp` | 37, 39 |
| `ch` | 42, 44 |
| `oh` | 46 |
| `cy` | 49, 51, 52, 55, 57, 59 |
| `lt` | 41, 43, 45 |
| `ht` | 47, 48, 50 |

上記以外は捨て、警告を出す。

### 6.7 警告
- 同時発音数が 16 を超える箇所は、小節・拍の位置を付けて警告する。自動では間引かない。
- 量子化で音長が 0 になったノートを警告する。

| 段階 | 内容 | 完了条件 |

### 8.1 特許についての調査（2026-10-17）

本ライブラリが YMF825 から採用する機能について、特許に触れる可能性を調べた。弁護士・弁理士による判断ではない。

- **結論**：採用する機能は、2001〜2002 年の MA-3（YMU762）の時点で公開済みと見られる。そのため、関連する特許があったとしても、存続期間（出願から約 20 年）は 2022 年頃までに満了している計算になる。また、それより後の出願は、公開済みの技術として新規性を欠く。以上から、特許に触れる可能性は低いと判断した。
- **機能ごとの初出**（主に二次情報による）

  | 機能 | 初出 |
  |---|---|
  | FM 合成の基本（Chowning 特許 US 4,018,121） | 1977 年成立、1990 年代半ばに満了 |
  | AR・DR・SR・RR・SL・TL・MUL・KSL などのパラメーター構成 | 1980 年代の OPM・OPN・OPL 系 |
  | 4 オペレーターの結線（OPL3 の 6 種） | OPL3（1988 年頃） |
  | 結線の追加 2 種、op3 の 2 つ目の帰還、29 種の波形、SR、XOF、EAM・EVB、detune | MA-3（2001 年） |
  | DAM・DVB の 4 段階 | MA-2（2000 年） |

  YMF825（2011 年）の FM 部分は、MA-3/MA-5 の仕組みを引き継いでいる。

- **根拠**
  - 一次情報：MA-3 カタログ（CATALOG No. LSI-4MU762A3、2002.9）に「FM の基本波形とアルゴリズムを MA-2 から改良し、detune などのパラメーターを追加した」とある。29 種・8 種という数の列挙はない。
  - 二次情報：bryc「Collecting info on Yamaha FM soundchips」「!Algorithms.md」（GitHub Gist）。29 種・8 種の初出が MA-3 であることは、この二次情報による。
- **調べていないこと**
  - 特許データベース（J-PlatPat など）での正式な検索。今回は Web 検索で見つかったものを確かめただけである（JP2790093B2 は 2015 年に満了、US9040800B2 は圧縮波形の技術で失効）。
  - YMF825 で新たに加わった技術の有無。ただし本ライブラリが使うのは音色パラメーターと結線だけで、チップの通信方式やシーケンサーは使わない。
- 本ライブラリに MA-3 より後の世代に固有の機能を加えるときは、同じ観点で初出を確かめる。
