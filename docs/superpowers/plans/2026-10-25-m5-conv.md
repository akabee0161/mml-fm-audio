# M5 SMF → MML 変換 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Domino などで作った SMF を、ゲームでそのまま鳴らせる MML に変換するコマンド（`npm run conv`）を `packages/conv` に作り、MML にドラムのサブトラック `R1`、`R2`、… を足す。

**Architecture:** 変換は段ごとに分けた純粋な関数の列にする：SMF を読む（`smf.ts`）→ チャンネルごとのノートと変化を取り出す（`extract.ts`）→ 量子化（`quantize.ts`）→ ループと曲の終わりを決める（`loop.ts`・`meter.ts`）→ トラックに割り当てる（`allocate.ts`）→ MML を書く（`writer.ts`）→ `parseMml` で解析し直す（`convert.ts`）。コマンド（`cli.ts`）は `convertSmf` を呼んでファイルと標準出力・標準エラーを扱うだけ。

**Tech Stack:** TypeScript 5.6、Node.js 22.18 以上（`node file.ts` の型を外す実行）、Vitest 2。依存のライブラリは足さない。

**Spec:** `docs/superpowers/specs/2026-10-25-m5-conv-design.md`（製品仕様は `docs/spec.md`、MML は `docs/mml.md`）

1. **Domino の既定の分解能 480 と、打ち込みのずれ（数ティックの前後）** → 普通の 16 分音符は普通の長さに、3 連符は 3 連の長さにそろう。Task 4 のテスト「480 の分解能で ±5 ティックずれた 16 分音符と 8 分の 3 連符」で押さえる。

**Files:**

**Interfaces:**

  ```ts
  export type QuantizeUnit = (typeof QUANTIZE_UNITS)[number];
  /** Extracted と同じ形で、すべての tick が整数。discarded はそのまま引き継ぐ */
  ```

- [ ] **Step 1: 失敗するテストを書く**

- 「32 分音符単位（12 ティック）にそろえる」：on 13.2・off 35 → 12・36。
- 「480 の分解能で ±5 ティックずれた 16 分音符と 8 分の 3 連符」：1 拍目に 16 分音符 4 つ（SMF の tick 0・125・235・365、長さ約 110）、2 拍目に 8 分の 3 連符 3 つ（480・640・800 から ±5）→ 1 拍目の on が 0・24・48・72、2 拍目の on が 96・128・160（3 連の 32 ティック）。
- 「普通の 32 分音符は 3 連に化けない」：on 12・24・36 は 12・24・36 のまま。
- 「長さが 0 になったノートは単位 1 つ分にし、警告する」：on 13・off 15（32 分音符単位）→ 12・24、警告 1 件。
- 「--quantize 16 では 24 ティック単位、3 連は 16 ティック」。
- 「変化・テンポ・マーカーも同じ拍の選択でそろえる」。

- [ ] **Step 2: 失敗を確かめる**

Run: `npx vitest run packages/conv/src/quantize.test.ts`
Expected: FAIL

- [ ] **Step 3: 実装する**

単位のティック `u = 384 / unit`、3 連の単位 `u * 2 / 3`。拍（`floor(t / 96)`）ごとに、その拍に入るノートのオン・オフの時刻を、普通の単位と 3 連の単位のそれぞれで最も近い格子へ寄せたときのずれの合計を比べ、3 連のほうが小さいときだけ 3 連を選ぶ（同じなら普通）。ノートのない拍は普通の単位。各時刻は、その時刻の属する拍の選択でそろえる。

  ```ts
  export function toMmlVolume(channelVolume: number, expression: number, velocity: number): number
  // writer.ts
  export function writeMml(tracks: PlannedTrack[], song: Quantized, loop: LoopRange, meter: Meter): string
  // convert.ts
  export interface ConvReport {

  }

  export function convertSmf(bytes: Uint8Array, options?: { quantize?: QuantizeUnit }): ConvertResult // 既定 32。エラーは ConvError
  ```

書き方の決まり（設計 §6）：
- 1 行目は `J`：`t`（tick 0 には必ず。SMF にテンポがなければ 120）・`L`・`E` と休符だけ。BPM は小数第 2 位までに丸め、末尾の 0 は書かない。1〜999 を外れたら ConvError。
- トラックの行の順は `J`、`allocateTracks` の順。初めの音色 0、パン 64、チャンネルボリューム 100、エクスプレッション 127（GM の初期値）。
- 音長：`1 2 4 8 16 32 3 6 12 24 48`（付点 1 つまで）でちょうど表せるときはそれ、ほかは `%N`。
- ノートのオン位置で `@`・`p`・`o` と `v`（`toMmlVolume`）を、前と違うときだけ書く。ノートの途中の `v`（ボリューム・エクスプレッションの変化）と `B` は、ノートをタイで分けてその位置に書く。休符の途中の `B` は、休符を分けてその位置に書く。
- ベンドは `Math.round` したセント。±1200 を超えたら ConvError（位置つき）。値が変わらない `v`・`B` は書かない。
- ノート番号 12 未満・120 以上は `o` で書けないので ConvError（位置つき）。
- ドラムは `drumNames` のドラム名で書き、長さは次の打撃まで（最後は `E` まで）。ドラムの `v` は打撃ごとに `toMmlVolume`。

- [ ] **Step 1: 失敗するテストを書く**

- volume：`toMmlVolume(100, 127, 100) === 12`、`(127, 127, 127) === 15`、`(100, 127, 0) === 0`、`(1, 1, 1) === 1`、`(127, 127, 64) === 11`。
- 「C-E-G の和音と 4 拍のメロディが、parseMml で同じノートになる」：`convertSmf(buildSmf(...))` の `mml` を `parseMml` に通し、各トラックの note の tick・note・gate・volume・pan・program が期待どおり、errors が空。
