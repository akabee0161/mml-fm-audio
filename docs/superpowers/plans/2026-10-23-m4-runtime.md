# M4 ゲーム向け API・効果音・音量とフェード 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ゲームから BGM と効果音を MML で鳴らすための API `FmAudio`（`packages/runtime`）を作り、ゲームのリポジトリへコピーして使えるようにする。

**Architecture:** 1 つの AudioWorklet のノードに、BGM 用 16 ボイスと効果音用 4 ボイスの 2 つの割り当てと 2 つの出力を持たせる。`FmAudio` は BGM 用の `Player` 1 つと効果音用の `Player` 複数を 25 ms ごとに pump し、`GainNode`（BGM のフェード・BGM・効果音・master）とスピーカー風フィルターを通して出力する。`Player` は先読みの範囲だけを少しずつ作る形に直し（ISSUES #11）、一時停止・再開を持つ。

**Tech Stack:** TypeScript 5.6、Vite 5、Vitest 2、Web Audio（AudioWorklet・GainNode・BiquadFilterNode）、playwright-core（ヘッドレス Chromium）。

**Spec:** `docs/superpowers/specs/2026-10-23-m4-runtime-design.md`（製品仕様は `docs/spec.md`、MML は `docs/mml.md`）

## Review Focus

1. **BGM の差し替えをすばやく繰り返す**（`playBgm` を 25 ms より短い間隔で何度も呼ぶ）→ 前の BGM の音が鳴り残らず、最後に渡した曲だけが鳴る。Task 5 のテスト「playBgm を続けて呼ぶと前の Player を止める」で押さえる。
2. **一時停止のときに先読みで送り済みだったノート** → 再開後に失われず、鳴らし直しもされない（同じノートが 2 回ノートオンされない）。Task 4 のテスト「先読みで送り済みのノートは再開後に 1 回だけ鳴る」で押さえる。
3. **フェード中の `playBgm`・`pauseBgm`・`stopBgm`** → 例外を投げず、フェードの倍率が次の曲に残らない（次の曲が無音にならない）。Task 6 のテスト「フェード中に playBgm すると新しい曲はフェードの倍率 1 で鳴る」で押さえる。
4. **`resume()` を呼ぶ前にタブが裏に回り、表に戻る** → AudioContext を勝手に `resume` しない（自動再生の制限に触れない）。Task 6 のテスト「裏に回る前から止まっていたら、表に戻っても resume しない」で押さえる。
5. **病的な MML を BGM にする**（`A L [[t120 c%1]200]200` など）→ 1 回の pump が 1 周のノート数に比例して長くならない。Task 3 の実測（`npm run measure:player`）で押さえる。

- [ ] **Step 5: 実装する**

`generatePass` と、待ち行列全体の `sort` をやめる。方法：

- トラックごとに読み位置（何周目か、`events` の添字、そのトラックの「最後にノートオンしたノート」）を持つ。
- `pump(now, horizon)` では、各トラックについて、次のイベントの時刻が `horizon` より前のあいだ、そのイベントのアクション（ノートオンならノートオンとノートオフの 2 つ）を作って、時刻順に取り出せる 2 分ヒープに入れる。ヒープの順は今の `compare`（時刻 → 種類 → トラック → seq）。
- 周回の終わり（`tick >= loopEnd`、ループしない曲は最後のイベント）に来たら、次の周の `loopStart` 以上の最初のイベント（二分探索か、構築時に求めた添字）へ移り、「最後のノート」を忘れる。ループしない曲は全トラックが終わったら生成済みとする。
- その後、ヒープの先頭の時刻が `horizon` より前のあいだ取り出して送る。
- 1 周にイベントのないトラックが、周を進めるだけで止まらないことがないよう、周の頭の時刻が `horizon` 以上なら止める。
- `seq` は作った順に振る。同じトラックの中では今と同じ順になる。

### Task 4: Player の一時停止・再開と、鳴る時刻の取得

**Files:**
- Modify: `packages/sequencer/src/player.ts`
- Test: `packages/sequencer/src/player.test.ts`

**Interfaces:**
- Consumes: Task 3 の `Player`
- Produces:
  - `pause(nowFrame: number): void`：持続中のノート（ノートオンの時刻が `nowFrame` より前で、ノートオフが `nowFrame` 以上）を `cancel` でキーオフし、以後 `resume` まで何も送らない。ノートオンの時刻が `nowFrame` 以上の送り済みのノートも `cancel` し、再開後に送り直す。一時停止中・停止後の `pause` は何もしない。
  - `resume(nowFrame: number): void`：一時停止した位置から続ける。以後のすべての時刻を `nowFrame − 一時停止した nowFrame` だけ後ろへずらす。一時停止の時点で持続中だったノートは鳴らし直さず、その残りの `noteOff`・`setPitchBend`・`setVolume` も送らない。一時停止していなければ何もしない。
  - `get paused(): boolean`
  - `loopFrame(pass: number): number`：`pass` 回目（1 以上）の周の頭（`L` の位置）が鳴る時刻（サンプル番号。一時停止のずれを含む）。ループしない曲で呼ぶと `RangeError`。
  - `get endFrame(): number | null`：ループしない曲の終わり（`song.length` のティック）が鳴る時刻。ループする曲では `null`。
  - `stop()` は一時停止中でも働く（キーオフ済みのノートを重ねて `cancel` しない）。
