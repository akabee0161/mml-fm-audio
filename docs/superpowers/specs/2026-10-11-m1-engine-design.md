製品仕様は `docs/spec.md`（v0.1、2026-10-09）。本書はその M1（「engine：4 オペレーター FM を 1 音、AudioWorklet で鳴らす」）と、リポジトリの土台を作るための設計である。

## 1. 目的と完了条件

- 目的：仕様書 §0 のとおり、ankardo のブラウザゲームで使う FM 音源の、最初の 1 音を鳴らす。
- 完了条件（仕様書 §7 の M1）：

  - YMF825 の音色データを変換し、試聴できる。
- 依頼者が公開 URL を PC とスマートフォンで開き、試聴して判断する。

## 3. 音色形式

### 3.1 一次資料で確かめた結果

YMF825_sample（Copyright (c) 2017 Yamaha Corporation, MIT License）の `manual/fbd_spec1.md`、`fbd_spec3.md`、`algo.png`、`ws.png`、`tonedata/sysexspec.md`、`tonedata/tonedata.txt` で確かめた。

仕様書の暫定値と合っていた点：

- アルゴリズムは 8 種。0〜1 が 2 オペレーター、2〜7 が 4 オペレーター。
- 値の範囲：AR・DR・SR・RR・SL は 0〜15、TL は 0〜63、KSL は 0〜3、KSR・XOF・EAM・EVB は 0/1、DAM・DVB は 0〜3、FB は 0〜7、WS は 0〜31、LFO は 0〜3、DT は 0〜7、MULTI は 0〜15。

仕様書から直す点・足す点：

1. **`bo`（基本オクターブ、0〜3）を音色全体の項目として足す。** 0：×2、1：×1、2：×1/2、3：×1/4。
2. **帰還を持つのはオペレーター 1 と 3 のみ。** 音色データでも FB 欄があるのは op1 と op3 だけである。op3 の帰還は、結線図で帰還が描かれているアルゴリズム 2 と 5 でのみ有効とする。op2・op4 の `fb` は無視する。
3. **`mul` は線形でない。**

   | `mul` | 0 | 1〜9 | 10, 11 | 12, 13 | 14, 15 |
   |---|---|---|---|---|---|
   | 倍率 | 1/2 | 値のまま | 10 | 12 | 15 |

4. **波形は 29 種。** 番号 15、23、31 は空き。空き番号はサインで代替し、警告を出す。
5. 公開されている値はそのまま使う。

   | 項目 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
   |---|---|---|---|---|---|---|---|---|
   | `lfo`（Hz） | 1.8 | 4.0 | 5.9 | 7.0 | | | | |
   | `amDepth`（dB） | 1.3 | 2.8 | 5.8 | 11.8 | | | | |
   | `vibDepth`（cent） | 3.4 | 6.7 | 13.5 | 26.8 | | | | |
   | `ksl`（dB/oct） | 0 | 3 | 1.5 | 6 | | | | |
   | `fb`（rad） | 0 | π/16 | π/8 | π/4 | π/2 | π | 2π | 4π |

6. 公開されていない値（エンベロープの時間、`dt` の量、TL・SL の 1 段あたりの dB）は独自に決める（§4.3）。

### 3.2 アルゴリズムの結線（algo.png より）

`→` は左のオペレーターが右を変調すること、`+` は出力で加算することを表す。`(fb)` は帰還を持つ。

| alg | 結線 | 出力するオペレーター |
|---|---|---|
| 0 | 1(fb) → 2 | 2 |
| 1 | 1(fb) + 2 | 1, 2 |
| 2 | 1(fb) + 2 + 3(fb) + 4 | 1, 2, 3, 4 |
| 3 | (1(fb) + (2 → 3)) → 4 | 4 |
| 4 | 1(fb) → 2 → 3 → 4 | 4 |
| 5 | (1(fb) → 2) + (3(fb) → 4) | 2, 4 |
| 6 | 1(fb) + (2 → 3 → 4) | 1, 4 |
| 7 | 1(fb) + (2 → 3) + 4 | 1, 3, 4 |

2 オペレーターのアルゴリズム（0、1）では、op3・op4 は計算しない。音色 JSON の `ops` は 2 要素でも 4 要素でもよい。

### 3.3 波形（ws.png より）

| 番号 | 形 |
|---|---|
| 0〜5 | サインを元にした 6 種：サイン（0）、正の半波のみ（1）、全波整流（2）、第 1・第 3 の 1/4 周期だけ立ち上がり部分（3）、倍速サインを前半のみ（4）、倍速の全波整流を前半のみ（5） |
| 6、7 | 矩形（6）、両端に向かって急に立ち上がる対数風の形（7） |
| 8〜13 | 0〜5 の山の頭を平らに切った形 |
| 14 | 前半だけの正の矩形 |
| 16〜21 | 0〜5 のサインを三角波に置き換えた形 |
| 22 | 第 1・第 3 の 1/4 周期だけの正の矩形 |
| 24〜29 | 0〜5 のサインを鋸歯状波に置き換えた形 |
| 30 | 第 1 の 1/4 周期だけの正の矩形 |

形は ws.png を見ながら数式で作り、Vitest で代表点（0、1/8、1/4、1/2、3/4 周期）の値を確かめる。

### 3.4 音色 JSON

```json
{
  "id": 0,
  "name": "GrandPiano",
  "kind": "fm",
  "bo": 0,
  "alg": 3,
  "lfo": 1,
  "ops": [
    { "wave": 0, "mul": 1, "dt": 0, "tl": 39, "ar": 15, "dr": 7, "sl": 6, "sr": 0, "rr": 0,
      "ksl": 0, "ksr": 0, "fb": 3, "am": 0, "amDepth": 0, "vib": 0, "vibDepth": 0, "xof": 0 }
  ]
}
```

（値は形式の説明用。実際の値は変換結果に従う。）

- `id` は GM の楽器番号（0〜127）。番号を割り当てない音色は `null`。
- 検証：範囲外の値、`ops` の要素数がアルゴリズムと合わない（alg 0〜1 で 2 未満、alg 2〜7 で 4 未満）場合はエラーとし、項目名（例：`ops[2].tl`）と理由を返す。余分なオペレーターは無視する。

### 3.5 YMF825 の音色データの変換

- `tonedata.txt` は 1 音色が `Name:`・`Author:`・41 バイト（`sysexspec.md` の p0〜p40、16 進）の 3 行。18 音色ある。
- `tools/` のスクリプトで読み、`voices/ymf825/gm.json`（16 音色）と `voices/ymf825/unassigned.json`（2 音色）に書き出す。
- GM の楽器番号の割り当て：

  | 音色 | GM | 音色 | GM |
  |---|---|---|---|
  | GrandPiano | 0 | NylonGuiter | 24 |
  | BrightPiano | 1 | PickBass | 34 |
  | E.Piano | 4 | TenorSax | 66 |
  | Harpsichord | 6 | Flute | 73 |
  | Vibes | 11 | SquareLead | 80 |
  | RockOrgan | 18 | SawLead | 81 |
  | ChurchOrgan | 19 | NewAgePd | 88 |
  | Harmonica | 22 | TnklBell | 112 |

- Rim Shot と Castanet は GM のメロディ楽器に当てはまる番号がないため `id: null` で `unassigned.json` に置き、M2 のドラム音色作りの材料にする。
- 元データの出典とライセンス全文を `voices/LICENSE-YMF825.txt` に収める（仕様書 §3.5）。

## 4. 音源エンジン（packages/engine）

### 4.1 方式

浮動小数点と波形テーブルで計算する（検討した案：実機風の整数演算＝対数サイン表と指数表、WASM。前者は YMF825 の内部表が非公開で実機に近づく保証がなく手間に見合わない、後者は仕様書で実測後に検討と決まっているため外した）。

### 4.2 分け方

| ファイル（目安） | 役割 |
|---|---|
| `waveforms.ts` | 29 種の波形表（1 周期 1024 点）を作る |
| `envelope.ts` | エンベロープ（段階の遷移と dB の計算） |
| `algorithms.ts` | 8 種の結線の定義 |
| `voice.ts` | 4 オペレーターと LFO を使って 1 ボイスを計算する |
| `voiceData.ts` | 音色 JSON の型と検証 |
| `processor.ts` | AudioWorkletProcessor。メッセージの待ち行列と `voice.ts` をつなぐだけ |
| `index.ts` | メインスレッド側：Worklet の読み込みと、メッセージ送信の関数 |

`processor.ts` 以外は AudioWorklet に依存せず、Vitest で Node 上で検査できる。`processor.ts` は Vite で 1 ファイルにまとめて `audioWorklet.addModule` で読む（まとめ方は計画の段階で動かして確かめる）。

### 4.3 計算

- **周波数**：ノート番号から平均律（A4＝440 Hz）で求め、`bo` の倍率、`mul` の倍率、`dt` を掛ける。
  - `dt`（暫定）：0〜7 を `[0, +3, +6, +9, 0, -3, -6, -9]` cent とする。
- **波形**：1024 点の表を補間せずに引く。
- **変調**：変調側の出力（−1〜1）に係数を掛けて、搬送側の位相（ラジアン）に足す。係数は暫定で 4π とし、耳で調整する。
- **帰還**：直前 2 サンプルの出力の平均 × FB 値（§3.1）を、自身の位相に足す。
- **エンベロープ**：減衰量を dB で持つ（0 dB が最大、96 dB 以上を無音とする）。
  - 段階：アタック → ディケイ（SL まで）→ サステイン（SR で減衰）→ リリース（キーオフ後、RR で減衰）。`xof` が 1 ならキーオフを無視する。
  - レート（暫定）：レート 0 は変化しない。1〜15 は 1 段ごとに速さを 2 倍にする。dB/秒の基準値は試聴で決める。SR＝0 で音量を保つのは IF 仕様書のとおり。
  - アタックは指数的に 0 dB へ近づける。
  - TL は 1 段 0.75 dB、SL は 1 段 3 dB（暫定）。
  - KSR：1 のとき、ノート番号が高いほど実効レートを上げる。KSL：§3.1 の dB/oct で、C4 より高い音を下げる（基準音は暫定）。
- **LFO**：音源全体で 1 つの三角波。速さは鳴っている音色の `lfo` で決める。`am`・`vib` が 1 のオペレーターに、深さ（§3.1）に応じてトレモロとビブラートをかける。
- **出力**：出力するオペレーター（§3.2）の和を 1 ボイスの出力とし、音量の係数（暫定）を掛ける。16bit 相当の丸め（既定オン）を経て、左右に同じ値を出す。
- エンベロープが無音に達したボイスは計算しない。

### 4.4 メインスレッドとのやり取り

`port.postMessage` で次のメッセージを送る。

| メッセージ | 内容 |
|---|---|
| `setVoice` | 音色 JSON（メインスレッドで検証済み） |
| `noteOn` | `note`（0〜127）、`time`（サンプル番号） |
| `noteOff` | `time`（サンプル番号） |
| `setQuantize` | 16bit 丸めのオン・オフ |

- `time` は AudioContext のサンプル番号。Worklet は時刻順の待ち行列に入れ、その時刻のサンプルから反映する。過去の時刻は直ちに反映する。
- M1 の鍵盤操作では、現在の時刻を送る。
- Worklet は、空き番号の波形を代替したときなどの警告を `port` でメインスレッドに返す。

## 5. demo（demo/）

- **開始ボタン**：ブラウザの自動再生の制限のため、押されたら AudioContext を開始して Worklet を読み込む。
- **音色の選択**：`gm.json` と `unassigned.json` の 18 音色を一覧で選ぶ。
- **音色 JSON の貼り付け欄**：貼り付けた JSON を検証して読み込む。エラーは項目名と理由を表示する。
- **パラメーター表示**：選んだ音色の値を読み取り専用の表で見せる。
- **鍵盤**：画面上に 2 オクターブ。オクターブを上下に切り替えられる。Pointer Events でタッチとマウスの両方に対応する。PC のキーボードは `a s d f g h j k` を白鍵、`w e t y u` を黒鍵に割り当てる。
- **警告の表示**：Worklet から返った警告を表示する。

## 6. テスト

- **Vitest**
  - 変換：GrandPiano の p0（`0b`）から `bo`＝0、`lfo`＝1、`alg`＝3 になるなど、既知のバイトから正しく読めること。18 音色すべてが検証を通ること。
  - `mul` の表、`dt` の表。
  - 波形表：代表点の値。
  - エンベロープ：アタックで 0 dB に届く、SL で止まる、SR＝0 で保つ、キーオフでリリースに移り無音に達する、`xof`＝1 でキーオフを無視する。
  - 結線：アルゴリズム 0 で op2 の TL を 63 にすると出力がほぼ無音になる、など出力オペレーターの確認。
  - 音色 JSON の検証：範囲外の値、`ops` の要素数。
- **ブラウザでの確認**：手元のヘッドレス Chromium で、ページが開く、Worklet が読み込まれる、鍵を押すと無音でない出力が出ることを確かめる。
- **最後の確認**：依頼者が公開 URL を PC とスマートフォンで開いて試聴する。
