# M4 設計：ゲーム向け API、効果音、音量・フェード（2026-10-23）

製品仕様は `docs/spec.md`（v0.4）。本書はその M4（「runtime：API、効果音の同時再生、音量・フェード」）の設計である。M3 の設計は `docs/superpowers/specs/2026-10-21-m3-sequencer-design.md`。

本書の「私の判断」は、依頼者と合意したものではなく、設計者（Claude）が決めたものである。依頼者が「好きに決めてよい」とした項目もこれに含める。依頼者が読んで違えば直す。「依頼者の決定」は、2026-10-23 の brainstorming で依頼者が決めたもの（設計者の案を依頼者が「提案どおりでよい」としたものを含む）である。

## 1. 目的と完了条件

- 目的：ankardo のブラウザゲームから、BGM と効果音を MML で鳴らせるようにする。
- 完了条件（spec §7 の M4）：ankardo のゲーム 1 本に組み込める。M4 では「組み込める API がそろい、別の Vite のプロジェクトへコピーして import すれば鳴る」ことまでを確かめる。実際にゲーム（キャラクタータクティクスを想定）へ組み込む作業は M4 に含めない（依頼者の決定）。

### 1.1 依頼者が確かめること

公開した試聴ページで、依頼者が次を確かめる。

| # | 確かめること | 確かめ方 |
|---|---|---|
| 1 | BGM が鳴り、ループする | 試聴ページの曲を「BGM 再生」で鳴らす。M3 と同じく `L` の位置から繰り返す |
| 2 | 効果音が BGM を消さずに重なる | BGM の再生中に効果音のボタンを続けて押す。BGM のノートが欠けず、効果音が重なって鳴る。同じボタンを連打すると重ねて鳴る |
| 3 | 音量が効く | master・BGM・効果音の音量を動かす。持続中のノートにもすぐ効く |
| 4 | フェードして止まる | 「フェードして停止」で BGM が約 1 秒で小さくなって止まる |
| 5 | 一時停止・再開 | 一時停止で BGM が止まり、再開でその位置から続く |
| 6 | タブを裏に回すと止まる | 再生中に別のタブへ切り替え、戻ると続きから鳴る |
| 7 | エラーのある MML は鳴らない | わざと間違えた MML を BGM 再生すると、エラーが出て鳴らない（鳴っている BGM も止まる） |

## 3. ゲーム向け API（packages/runtime）

spec §5.1 の API を、次のように変えて作る。

```ts
const audio = await FmAudio.init({ voices });       // voices は省略可（§3.1）
await audio.resume();                               // ユーザー操作の後に呼ぶ

const song = audio.load(mmlText);                   // parseMml の結果。エラーは song.errors
audio.playBgm(song);                                // BGM は同時に 1 曲。再生中なら差し替える
audio.stopBgm({ fadeMs: 500 });                     // fadeMs は省略可（省けばすぐ止める）
audio.pauseBgm(); audio.resumeBgm();

audio.playSe(seSong);                               // 効果音。複数同時に鳴らせる
audio.setVolume({ master: 1.0, bgm: 0.8, se: 1.0 }); // 一部だけ渡してよい
audio.setSpeakerFilter(true);
audio.on('loop' | 'end' | 'warning', handler);
```

### 3.1 初期化

- `FmAudio.init(options)`：AudioContext を作り（`options.context` で渡すこともできる。私の判断）、Worklet を読み込み、音色を登録する。
- `voices` を省くと、リポジトリの `voices/ymf825/gm.json`・`unassigned.json`・`voices/custom/drums.json` を同梱の音色集として登録する（依頼者の決定）。渡すときは、番号と音色の組の一覧にする（形は実装側に任せる）。
- 渡された音色は `validateVoice`・`validateDrum` で検査し、通らなければ `init` が例外を投げる（私の判断。MML と違い、ゲームを作る人の書き間違いなので、開発中に気づけるほうがよい）。
- `init` は自動再生の制限のため音を出せない状態で返ることがある。`resume()` をユーザー操作の後に呼ぶ。

### 3.2 エラーのある曲（依頼者の決定）

- `load` は例外を投げず、エラーを `song.errors` に入れて返す（spec §4.5 の「ゲーム実行時は例外を投げない」は守る）。
- エラーが 1 つでもある曲を `playBgm` に渡すと、何も鳴らさず、鳴っている BGM も止め、`warning` を 1 回出す。`playSe` に渡すと、何も鳴らさず `warning` を出す。
- エラーのあったトラックだけを無音にする動きは作らない。

### 3.3 BGM

- 同時に 1 曲。`playBgm` で再生中の BGM を差し替えるときは、前の BGM をすぐ止める（フェード中でも）。
- ループするかどうかは MML の `L` で決まる。`L` がない曲は最後まで鳴らしたら終わる。
- `stopBgm({ fadeMs })`：`fadeMs` の間に BGM の音量を 0 まで下げ、下げ終えたら止める（止め方は M3 の停止と同じで、送り済みの予約を捨て、持続中のノートをキーオフする）。フェード中も曲は進む。`fadeMs` を省くか 0 なら、すぐ止める（私の判断）。
- `pauseBgm()`：持続中のノートをキーオフし、曲の位置を止める。一時停止の時点より後にノートオンするはずのノートは、先読みで音源へ送り済みでも、再開後に鳴らす（失わない）。
- `resumeBgm()`：止めた位置から続ける。一時停止の時点で持続中だったノートは鳴らし直さず、次のノートオンから鳴らす（私の判断）。
- 一時停止中・フェード中の `pauseBgm`・`resumeBgm`・`stopBgm` の組み合わせの細部は実装側に任せる。ただし、どの順で呼んでも例外を投げず、音が鳴り残らないこと。

### 3.4 効果音（依頼者の決定）

- 効果音も MML で書いた曲として扱う（spec §5.2）。`R` トラックのドラムも使える。
- 効果音は BGM とは別のボイスで鳴らす。BGM のノートが効果音に消されることはない。
- 効果音用のボイスは 4 つ（暫定。M2 の実測で iPhone SE は 16 ボイスで 56.9 %。20 ボイスで約 71 % の見積もり）。BGM 用は今までどおり 16。
- 効果音用のボイスが足りなければ、効果音のうち最も古く鳴らしたノートを止めて使う（今の `VoicePool` の割り当てと同じ）。
- 同じ効果音を、前のものが鳴っている間にもう一度 `playSe` すると、重ねて鳴らす。
- `L` のある曲を効果音として鳴らした場合の扱いは実装側に任せる（ループさせてもよいし、`L` を無視して最後まで鳴らしてもよい）。どちらにしたかを `docs/api.md` に書く。

### 3.5 音量・スピーカー風フィルター（私の判断）

- `setVolume({ master, bgm, se })`：それぞれ 0〜1。渡したものだけ変える。持続中のノートにもすぐ効く（プチッと鳴らない程度の短い時間で移ってよい）。フェード中に `bgm` を変えたときは、フェードの倍率と掛け合わせる（フェードは `bgm` の音量とは別の倍率で持つ）。
- 範囲外・数でない値は、音源の他の関数と同じく `RangeError` を投げる（MML のエラーではないため）。
- `setSpeakerFilter(enabled)`：spec §2.1 のハイパス（暫定 300 Hz）とローパス（暫定 7 kHz）を、Web Audio の `BiquadFilterNode` で出力の最後に入れる。既定はオフ（spec に既定がなく、周波数は M6 で決めるため）。

### 3.6 イベント（私の判断）

- `on('loop', handler)`：BGM が `L` の位置へ戻ったとき。
- `on('end', handler)`：`L` のない BGM が曲の終わり（`song.length` の時刻）に来たとき。`stopBgm` では呼ばない。
- どちらも、音が実際に鳴る時刻（AudioContext の `currentTime` がその位置に来たとき）に呼ぶ。先読みで送った時点では呼ばない。遅れは pump の間隔（25 ms）程度まで許す。
- `on('warning', handler)`：音源の警告（未登録の音色など）と、エラーのある曲を渡したとき。
- 効果音にはイベントを出さない。

### 3.7 先読みとタブが裏に回ったとき

- `FmAudio` が内部のタイマーで `Player.pump` を呼ぶ。間隔と先読みは試聴ページと同じ 25 ms・0.1 秒。
- タブが裏に回ったら（`visibilitychange` で `document.hidden`）AudioContext を `suspend` し、表に戻ったら `resume` する（依頼者の決定）。曲の位置は止めた時点から続く。止める前から AudioContext が止まっていた（`resume()` を呼ぶ前など）ときは、表に戻っても `resume` しない。この動きは切り替えられなくてよい。

## 4. 音源（packages/engine）

- BGM 用 16 ボイスと効果音用 4 ボイスを、別々の割り当て（`VoicePool`）で持つ（依頼者の決定）。
- 1 つの Worklet のノードに 2 つの出力（BGM、効果音）を持たせる（私の判断）。ノードを 2 つにするより、音色の登録と負荷の集計が 1 か所で済むため。2 つの出力は、それぞれ `GainNode`（BGM の音量とフェード、効果音の音量）を通して master の `GainNode` で合わせる。
- `noteOn` に「BGM か効果音か」の指定を足す。省けば BGM（試聴ページの鍵盤・リズムは BGM 側のまま）。
- 負荷の集計（`setLoadReport`）は両方のボイスを合わせて 1 つの数にする。ボイス数も合計で出す。
- 16 bit 相当への丸めは出力ごとに行ってよい。

## 5. ゲームへのコピー（依頼者の決定）

- ゲームのリポジトリへは、pixel-asset-forge と同じくフォルダごとコピーする。ただしコピーするのは、ゲームが使う部分だけ：`packages/engine`・`packages/sequencer`・`packages/runtime` のソース（テストを除いてよい）と、`voices/` の JSON・`voices/LICENSE-YMF825.txt`。`demo/`・`tools/`・`docs/` は入れない。
- コピーした側では直さない。直すときは本体で直してからコピーし直す。コピーに `UPSTREAM.md` を置き、元の commit・コピーした日・「ここでは直さない」ことを書く。
- コピーする道具を `tools/` に作る（例：`npm run export:runtime -- <コピー先>`）。コピー先に既にあれば、中身を入れ替える（コピー先が symlink なら止める。forge の `export.py` の教訓）。
- コピーしたものは、ゲームのリポジトリの npm workspaces やパッケージ名の解決に頼らずに import できること。そのため `packages/runtime` から `engine`・`sequencer` へは相対パスで import する（私の判断）。
- 前提：ゲームは Vite でビルドする（Worklet を `?worker&url` で読み込むため）。キャラクタータクティクスは Vite。この前提を `docs/api.md` に書く。

## 6. Player（packages/sequencer）

### 6.1 ISSUES.md #11 の修正（私の判断）

- 今は、各周回の頭（`generatePass`）で 1 周分のアクションをすべて作り、待ち行列全体を並べ直す。1 周に 1 回メインスレッドが止まる（`A L [[t120 c%1]200]200` で 60〜150 ms、16 トラック × 4 万ノート・`t999` で約 1.5 秒）。
- これを、先読みの範囲に要る分だけを少しずつ作る形に直す（例：トラックごとの読み位置と、時刻順に取り出せる構造）。方法は実装側に任せる。
- 目標：1 回の `pump` の時間が、1 周のノート数ではなく、その `pump` で送るイベントの数に応じて決まること。
- 計り方（必須）：試聴ページと同じ条件（25 ms ごとに `pump`、先読み 0.1 秒、48 kHz）で、少なくとも次の入力について、直す前と後の「合計時間」と「1 回の `pump` の最大時間」を測り、結果を最終の報告と `ISSUES.md` #11 を消すコミットのメッセージに書く。
  - `A L [[t120 c%1]200]200`
  - 16 トラック × 4 万ノート・`t999`（#11 で測ったもの）
  - 試聴曲 `demo/songs/m3-demo.mml`
- 「手書きでは出ない」と判断する前に、必ず実測する。病的な入力で 1 回の `pump` が長いまま残るなら、その数字を依頼者に報告して判断を仰ぐ。

### 6.2 一時停止・再開、鳴る時刻の通知

- §3.3 の一時停止・再開と、§3.6 の `loop`・`end` を作るのに要る機能を足す。形は実装側に任せる。
- M3 の決まり（`L` の前から持続中のノートを鳴らし直さない、ループ終了を越えるノート、`v`・`B` の効く対象、送り済みノート一覧を捨てる #10 の修正）は変えない。

## 7. 引数の検査

- `FmEngine.cancel`：配列でない値を渡されたら `RangeError` を投げる（今は `ids.every` で配列以外のときに別の例外になる）。
- `ISSUES.md` #5：`operatorFrequency` と `waveValue` が範囲外の値を受けたら `RangeError` を投げる。`operatorFrequency` は発音ごと、`waveValue` は波形表を作るときだけ呼ばれるので、検査の負荷は問題にならない。直したら #5 の行を消す。
- `FmAudio` の公開関数は、引数を検査して理由つきの `RangeError` を投げる（MML の中身のエラーは §3.2 のとおり例外にしない）。

## 8. 試聴ページ（demo）

- MML の欄の再生・停止を `FmAudio` の BGM で行う。「BGM 再生」「停止」「フェードして停止（1 秒）」「一時停止」「再開」を置く。
- 効果音のボタンを 3〜4 個置く。それぞれ手書きの短い効果音の MML（`demo/songs/` に置く。例：決定音、キャンセル音、ドラムを使った打撃音）を鳴らす。
- master・BGM・効果音の音量のスライダーを置く。
- スピーカー風フィルターのオン・オフを置く。
- 鍵盤・16 音・ドラム・リズム・負荷の表示は残す（鍵盤とリズムは音源を直接使ってよい）。ページの中で AudioContext と Worklet のノードは 1 つにする。
- `loop`・`end` を受けたら、画面に回数などを出す（確認 1 の助けにする）。

## 9. 確かめ方（実装側）

- Vitest：`FmAudio` の振る舞い（エラーのある曲、差し替え、フェード、一時停止・再開、イベントの時刻、音量の範囲検査）は、AudioContext と音源を差し替えたテストで確かめる。`Player` の一時停止・再開と #11 の修正後の送る順・時刻は、M3 の `player.test.ts` と同じ形で確かめる。効果音のボイスが BGM のボイスを奪わないことは `VoicePool` 側のテストで確かめる。
- `npm run check:browser`：試聴ページで BGM と効果音が同時に鳴り、出力が無音でないことを確かめる。加えて、§5 の道具で一時フォルダの最小の Vite プロジェクトへコピーし、ビルドして、ヘッドレス Chromium で `FmAudio` から BGM と効果音が鳴ることを確かめる。サーバーのメモリが少ないため、Chromium は 1 つずつ動かす。
- 負荷：§6.1 の実測。
- 完了を報告する前に `npm test`、`npm run build`、`npm run check:browser` を通す。
