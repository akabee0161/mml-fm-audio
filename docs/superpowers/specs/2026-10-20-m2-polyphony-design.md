# M2 設計：16 音同時発音、ステレオ、ノイズ、ドラム 8 種（2026-10-20）

製品仕様は `docs/spec.md`（v0.2）。本書はその M2（「16 音同時発音、ステレオ、ノイズ、ドラム 8 種」）の設計である。M1 の設計は `docs/superpowers/specs/2026-10-11-m1-engine-design.md`。

本書の「私の判断」は、依頼者と合意したものではなく、設計者（Claude）が決めたものである。依頼者が読んで違えば直す。

## 1. 目的と完了条件

- 目的：M3（MML）・M4（ゲーム向け API）の土台として、複数の音色を同時に、左右に振って鳴らせる音源にする。ドラムを鳴らせるようにする。
- 完了条件（spec §7 の M2）：16 音同時発音時の負荷を、PC と手元のスマートフォン（Google Pixel 7a、iPhone SE）で実測し、記録する。
- 負荷は**数字を記録するだけ**とし、合格の線は設けない（依頼者の決定）。同時発音数の上限の見直し（spec §9 の未決事項 4）も、M2 では記録だけして決めない（依頼者の決定）。
- 16 音は暫定の値である（spec §2.1）。

### 1.1 依頼者が確かめること

公開した試聴ページで、依頼者が次を確かめる。

| # | 確かめること | 確かめ方 |
|---|---|---|
| 1 | 和音が鳴る | 画面の鍵盤や PC のキーで複数の鍵を同時に押す |
| 2 | 16 音が同時に鳴り、17 音目では最も古い音が止まって新しい音が鳴る | 「16 音を鳴らす」ボタンで 16 音を鳴らしたまま、鍵盤を押す |
| 3 | ステレオになっている | パンのつまみを左右に振ってから鳴らし、イヤホンで左右から聞こえるかを聞く |
| 4 | ドラム 8 種（bd・sd・ch・oh・cy・lt・ht・cp）がそれらしく聞こえる | 8 個のボタンで 1 つずつ鳴らす。ノイズの音もここで聞く |
| 5 | ドラムと FM の音を重ねても、音が割れたり途切れたりしない | 和音を押さえたまま、ドラムのボタンかリズムを鳴らす |
| 6 | 16 音同時の負荷 | PC・Pixel 7a・iPhone SE で試聴ページを開き、2 のボタンを押して、画面に出る処理時間の数字を設計者に伝える。記録は設計者が書く。iPhone SE の世代もこのとき伝える |

テストや数値で確かめられることは、実装側が Vitest とヘッドレス Chromium で確かめる（§7）。

## 2. 範囲

### 2.1 作るもの

- 16 ボイスの同時発音と、ボイスの奪い合い（最も古く発音したボイスを止める）。
- ボイスごとのパンと、ステレオ出力。
- ホワイトノイズ発生器とドラム音色（spec §3.4 の形式）。
- ドラム 8 種の音色（暫定の音。M6 で調整してよい：依頼者の決定）。
- 負荷の計測と、試聴ページでの表示。実測結果の記録。
- 試聴ページ：和音、16 音ボタン、パン、ドラムのボタン、簡易なリズム、負荷の表示。
- `ISSUES.md` #4：残りの結線（alg 1/2/3/6/7）の出力を確かめるテスト。

## 3. 音源の構成（packages/engine）

### 3.1 ボイスの割り当て

- Worklet は `Voice` を 16 個持つ（`MAX_VOICES = 16`、1 か所で定義する）。
- 割り当て（私の判断）：
  1. 鳴っていない（`active` が false の）ボイスがあれば、そのうち 1 つを使う。
  2. なければ、最も古く `noteOn` したボイスを止めて使う（spec §2.2）。止めた音はその場で切れる。
- ボイスの割り当ては、Worklet に依存しない新しいモジュール（例：`voicePool.ts`）に書き、Vitest で確かめる。`processor.ts` は薄く保つ（CLAUDE.md）。

### 3.2 メインスレッドとのやり取り

音色は先に番号付きで登録し、`noteOn` では番号で指す。音には、メインスレッドが振る ID を付ける（私の判断）。ID により、`noteOff` が奪われた後の別の音を止めてしまうことを防ぐ。

| メッセージ | 内容 |
|---|---|
| `registerVoice` | `program`（0〜127 は FM 音色、128〜はドラム。spec §3.3）、音色（メインスレッドで検証済み） |
| `noteOn` | `id`（整数）、`program`、`note`（0〜127）、`pan`（0〜127、64 が中央）、`time`（サンプル番号） |
| `noteOff` | `id`、`time` |
| `setQuantize` | 16bit 丸めのオン・オフ（M1 のまま） |
| `setLoadReport` | 負荷の報告のオン・オフ（§3.6） |

- M1 の `setVoice` は `registerVoice` に置き換える。
- 未登録の `program` の `noteOn` は鳴らさず、`warning` を返す。
- `noteOff` の `id` を持つボイスがない（すでに奪われた、鳴り終わった）ときは何もしない。
- 鳴っている最中に同じ `program` を登録し直したときは、鳴っている音は前の音色のまま鳴り終える（私の判断）。
- `FmEngine`（`index.ts`）の公開関数もこれに合わせて変える。`noteOn` は ID を振って返し、`noteOff` はその ID を受け取る。引数の検査は M1 と同じく `RangeError` を投げる。

### 3.3 ステレオ

- 各ボイスは `noteOn` で受け取ったパンを持つ。パンは音が鳴っている間は変わらない（MML の `p` は次の音から効くため。私の判断）。
- パンの効き方は等パワー（私の判断）：左 `cos θ`、右 `sin θ`。64 をちょうど中央（θ = π/4、左右とも約 0.707）にするため、`pan ≤ 64` では `θ = pan / 64 × π/4`、`pan > 64` では `θ = π/4 + (pan − 64) / 63 × π/4` とする（MML の `p64` や SMF の CC10=64 を中央として扱うため）。
- 16 ボイスの左右の和に、全体の係数 `MIX_GAIN`（暫定。初期値は 0.5、私の判断）を掛け、左右それぞれを丸め（または `clampSample`）にかける。
  - M1 の 1 音と比べて中央の音は約 0.35 倍の大きさになる。依頼者の確認 5（割れない）と 7（M1 が壊れていない）で聞いて、値を調整してよい。`README.md` の暫定値の一覧に加える。

### 3.4 LFO

- spec §2.1 のとおり 1 系統のまま。速さは、最後に `noteOn` した FM 音色の `lfo` で決める（M1 は最後に `setVoice` した音色。私の判断）。ドラムの `noteOn` では変えない。

### 3.5 ノイズとドラム

#### ドラム音色の形式

spec §3.4 の形式を使い、次の点を決める（spec §3.4 は「暫定」なので、ここで決めてよい）。

```json
{
  "id": 128,
  "name": "bd",
  "kind": "drum",
  "fm":    { "voice": { "...": "spec §3.2 の FM 音色" }, "note": 36, "level": 1.0 },
  "pitch": { "fromSemitone": 24, "toSemitone": 0, "decayMs": 40 },
  "noise": { "level": 0.1, "ar": 15, "dr": 10, "sl": 15, "rr": 12, "color": "white",
             "repeat": { "count": 3, "intervalMs": 12 } }
}
```

| 項目 | 範囲・意味 |
|---|---|
| `id` | 128〜。8 種の番号は §5 |
| `name` | 文字列 |
| `fm` | 省略可。`voice` は spec §3.2 の FM 音色（`validateVoice` で検証する）。`note` は 0〜127。`level` は 0〜1 |
| `pitch` | 省略可。`fm` がないときは書けない。音程を `fromSemitone` 半音から `toSemitone` 半音へ、`decayMs` を時定数として指数的に近づける（`offset = to + (from − to) × e^(−t / decayMs)`）。半音は −48〜48、`decayMs` は 0 より大きい |
| `noise` | 省略可。`level` は 0〜1。`ar` `dr` は 0〜15、`rr` は 1〜15、`sl` は 0〜15。`color` は `"white"` のみ。エンベロープはアタック → ディケイ（`sl` まで）→ その後は `rr` の速さで無音まで下がる（ドラムには `noteOff` が来ないため、`rr` を SL に達した後の減衰に使う。私の判断） |
| `noise.repeat` | 省略可（spec に新たに足す項目）。ノイズのエンベロープを `intervalMs` ごとに `count` 回かけ直す。クラップ（spec §3.4 の「ノイズを短く数回重ねる」）のため。`count` は 1〜8、`intervalMs` は 1〜100 |

- `fm` と `noise` の少なくとも一方が要る。
- ドラムは必ず鳴り終わらなければならない（鳴り終わらないとボイスが空かず、リズムを繰り返すたびにボイスが溜まるため）。そこで `fm.voice` の出力オペレーターは「`sl` が 15、または `sr` が 1 以上」でなければならない。`validateDrum` はこれを満たさないものをエラーにする（私の判断）。`xof` はドラムでは意味を持たない（`noteOff` を無視するため）。
- 検証は `voiceData.ts` に `validateDrum` として足し、M1 の `validateVoice` と同じ形（項目名と理由）でエラーを返す。`voiceData.ts` は他のファイルを import しない（CLAUDE.md）。
- `noise.repeat` を足したことは、spec §3.4 にも反映する（spec は正典ではなく製品仕様だが、形式の定義はここにあるため）。

#### 鳴り方

- ドラムも 16 ボイスの 1 つを使う。1 つのボイスが FM 部とノイズ部を両方鳴らす。
- `noteOn` の `note` は無視し、`fm.note` の高さで鳴らす。
- ドラムは `noteOff` を無視し、エンベロープが無音に達したら鳴り終える（私の判断。MML の音長でドラムが途中で切れないように）。`active` は、FM 部の出力オペレーターかノイズ部のどちらかが鳴っていれば true。
- ノイズ：Worklet に依存しない擬似乱数（例：xorshift）で、−1〜1 の一様な値を作る。種を固定できるようにして、テストで同じ結果を得られるようにする（私の判断）。
- ノイズのエンベロープは `Envelope` を使い回す。`Envelope.keyOn` は今 `FmOperator` を受け取るので、エンベロープに要る項目（ar・dr・sl・sr・rr・ksr・xof）だけの型を受け取るように広げる。ノイズでは `sr` に `noise.rr` を渡す（上の表のとおり SL に達した後は `rr` の速さで下がる）。
- FM 部の出力に `fm.level`、ノイズ部に `noise.level` を掛けて足し、そのボイスの出力とする。

### 3.6 負荷の計測

- Worklet は `process` 1 回の処理時間を測り、1 秒ごとに集計して `EngineReply` の新しい種類（例：`load`）で返す。返す値：平均・最大の処理時間（ms）、1 ブロックの長さ（ms）に対する平均の割合（%）、その 1 秒間に鳴っていたボイス数の最大、使った時計。
- 時計：`AudioWorkletGlobalScope` で `performance.now()` が使えるかはブラウザーによって違う可能性がある。使えればそれを使い、使えなければ `Date.now()` を使って平均だけを出す（1 ms 刻みでは 1 ブロックの最大値に意味がないため）。どちらを使ったかを画面に出す。各ブラウザーで何が使えるかは、計画か実装の最初に確かめる。
- 計測は `setLoadReport` でオンにしたときだけ行う。

### 3.7 ファイルの分け方（目安）

| ファイル | 変更 |
|---|---|
| `voicePool.ts`（新規） | 16 ボイスの割り当て、ID とボイスの対応、左右への足し込み |
| `noise.ts`（新規） | 擬似乱数のノイズ |
| `drum.ts`（新規）または `voice.ts` | ドラムの鳴らし方（音程の降下、ノイズ部、`repeat`）。`Voice` に足すか分けるかは計画で決める |
| `voice.ts` | 音色を `noteOn` で受け取る、パン、ドラム |
| `envelope.ts` | `keyOn` の引数の型を広げる |
| `voiceData.ts` | `DrumVoice` の型と `validateDrum` |
| `messages.ts`、`processor.ts`、`index.ts` | §3.2・§3.6 |

## 4. 試聴ページ（demo）

M1 の画面に次を足す。

- **和音**：M1 の `MonoNoteTracker`（押し直すと前の音を切る）を、押している鍵ごとに音を鳴らす作りに変える。キー（PC のキー、ポインター）ごとに `noteOn` の ID を覚え、離したらその ID で `noteOff` する。
- **16 音を鳴らす**：押すと、選んでいる音色で 16 音を鳴らし続け、もう一度押すと止める（私の判断）。音の高さは、音色の音域で聞き分けられるよう、C3 から 2 オクターブ半ほどに散らす。鳴らしたまま鍵盤を押すと 17 音目になる。
- **パン**：0〜127 のつまみ（既定 64）。次に鳴らす音（鍵盤、16 音、ドラム）に効く。
- **ドラム**：8 種のボタン。押すと 1 回鳴る。
- **リズム**（簡易でよい：依頼者の決定）：押すと固定のパターンを繰り返し、もう一度押すと止まる。8 種すべてが入った 1 小節のパターンを、テンポ 120 で鳴らす（私の判断）。メインスレッドから先読みしてサンプル時刻付きで送る（spec §2.2 のジッター対策）。
- **負荷の表示**：§3.6 の値を 1 秒ごとに表示する。表示しているときだけ計測をオンにする（例：「負荷を表示」のチェック。私の判断）。
- 音色の選択は FM 音色（18 種）だけとし、ドラムは選択肢に入れない（ドラムはボタンで鳴らす）。音色を選ぶと、その音色を `program` 0 番などの固定の番号に登録し直して鍵盤で使う、といった具体的な番号の扱いは計画で決める。
- `?debug` の `window.__mmlFmAudio.peak()` は、左右を別々に返せるようにする（ヘッドレス Chromium の確認で使う）。

## 6. 負荷の記録

- 置き場：`docs/load-measurements.md`（私の判断）。日付、端末、OS とブラウザーの版、音色、鳴らしたボイス数、§3.6 の値、音切れの有無を表で記録する。後のマイルストーンで測り直したら行を足す。

- 記録を書いたら、spec §9 の未決事項 4 に「M2 の実測は `docs/load-measurements.md`」と書き足す。判断はしない。
- 順番（依頼者の決定）：M1 と同じく、PR をマージ → 公開 → 依頼者が確認・実測 → 設計者が記録を書く。記録の文書を他の修正（例：確認 4 で直すドラム）と一緒に push するときは、その PR に含める。

## 7. 確かめ方（実装側）

- Vitest：
  - ボイスの割り当て（空きを使う、17 音目で最も古い音を止める、奪われた ID の `noteOff` は何もしない、鳴り終えたボイスを使い回す）。
  - パン（0 で右が 0、127 で左がほぼ 0、64 で左右が等しい）。
  - ノイズ（種が同じなら同じ列、値が −1〜1、平均がほぼ 0）。
  - ドラム（音程の降下、`noteOff` を無視して鳴り終える、`repeat` でエンベロープがかけ直される、FM 部・ノイズ部の片方だけでも鳴る）。
  - `validateDrum` と `voices/custom/drums.json` の 8 種がすべて検証を通ること。
  - `ISSUES.md` #4：alg 1/2/3/6/7 について、出力するオペレーターだけを TL=63 にすると無音になり、出力しないオペレーターを TL=63 にしても無音にならないこと（M1 の alg 0/4/5 のテストと同じ考え方）。直したら `ISSUES.md` の #4 の行を消す。
- `npm run check:browser`（ヘッドレス Chromium）：M1 の確認に加え、和音で振幅が増える、パン 0 で右がほぼ無音、ドラムのボタンで音が出る、16 音ボタンでエラーが起きない、負荷の値が届く。
- 完了の報告の前に `npm test`、`npm run build`、`npm run check:browser` を通す（CLAUDE.md）。
