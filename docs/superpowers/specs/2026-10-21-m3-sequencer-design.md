# M3 設計：MML の全命令とループ（2026-10-21）

製品仕様は `docs/spec.md`（v0.3）。本書はその M3（「sequencer：MML の全命令、ループ」）の設計である。M2 の設計は `docs/superpowers/specs/2026-10-20-m2-polyphony-design.md`。

本書の「私の判断」は、依頼者と合意したものではなく、設計者（Claude）が決めたものである。依頼者が読んで違えば直す。「依頼者の決定」は、2026-10-21 の brainstorming で依頼者が決めたもの（設計者の案を依頼者が「案どおりでよい」としたものを含む）である。

## 1. 目的と完了条件

- 目的：MML のテキストを解析し、音源（`packages/engine`）を鳴らすシーケンサーを作る。M4（ゲーム向け API）と M5（SMF → MML 変換）の土台にする。
- 完了条件（spec §7 の M3）：手書きの MML で BGM がループ再生される。

### 1.1 依頼者が確かめること

公開した試聴ページで、依頼者が次を確かめる。

| # | 確かめること | 確かめ方 |
|---|---|---|
| 1 | 手書きの曲が鳴り、`L` の位置から繰り返す | 試聴ページの曲（§5.2）を再生し、イントロが 1 回だけ鳴って、そのあと `L` の位置から繰り返すのを聞く。ループ終了を越える弱起のノートが、戻った後も持続するのを聞く |
| 2 | MML を書き換えて鳴らせる | 欄の MML を書き換えて（例：テンポ、音色、音符）再生し直す |
| 3 | 書き間違いがエラーとして出る | わざと間違えて（例：`c4&d4`、`[cdef]`）再生し、行番号・列番号と理由が出るのを見る |
| 4 | 音量・パン・ピッチベンド・`q` が効く | 曲の中のそれぞれの箇所を聞く（§5.2 で、どこで何を使っているかを画面に書いておく） |
| 5 | 止めると音が残らない | 再生中に停止を押す |
| 6 | M2 までの機能が壊れていない | 鍵盤、16 音、ドラム、リズム、負荷の表示を試す |

テストや数値で確かめられることは、実装側が Vitest とヘッドレス Chromium で確かめる（§7）。

## 2. 範囲

### 2.1 作るもの

- `packages/sequencer`（新規）：MML の解析、ティックから時刻への変換、音源を鳴らす再生器。
- spec §4.3 の全命令と、`q`（ゲートタイム。依頼者の決定）。
- `L` によるループ。
- 音源（`packages/engine`）への追加：音量、ピッチベンド、予約した発音の取り消し（§4）。
- 試聴ページ：MML の欄、再生・停止、エラーの表示、手書きの曲 1 曲（§5）。
- MML の文法の文書 `docs/mml.md`（依頼者の決定）。spec §4 からそこを指す。

### 2.2 作らないもの

| 機能 | 時期 |

| エラーのあったトラックだけを無音にして鳴らす動き、その切り替えの設定（spec §4.5） | M4（依頼者の決定）。M3 は、エラーを行番号・列番号・理由つきで報告するところまで。エラーは書いた人が直すもので、無音にするのはゲームに入ってしまったときの備え |

| 「何ティックかけてこの値まで変える」ピッチベンドの命令 | 作らない（依頼者の決定）。手で書くのを楽にするだけのもので、MIDI からの変換は `B` を並べれば表せる |
| 繰り返しの最後の回だけ抜ける `[ ... : ... ]`、ポルタメント | 必要になったら（依頼者の決定） |
| 和音記法（spec §9 の 5） | 必要になったら（spec のとおり） |
| 変換した MML を短くする工夫（細かい `B` の間引きなど） | M5 で決める（依頼者の決定） |
| 効果音、BGM と効果音の発音数の配分、フェード、`on('loop')` などのイベント | M4 |

## 3. MML（packages/sequencer）

spec §4 を基に、次のとおり決める。決めた内容は `docs/mml.md` に書き、spec §4 を更新する（§8）。

### 3.1 全体

- 1 行が 1 トラックへの記述。行頭のトラック名、空白（1 文字以上）、命令の順に書く。同じトラック名の行は、上から順に連結して解釈する（spec のとおり）。
- 連結した行の区切りは、命令と命令の間の空白と同じに扱う（私の判断）。そのため、タイ `&` や繰り返し `[ ]` は、同じトラックの次の行へまたいで書ける。エラーの行番号・列番号は、元のテキストの位置で示す。
- `;` から行末まではコメント。空行と、コメントだけの行は無視する。
- 大文字・小文字は区別する（依頼者の決定）。命令は小文字で、`B` と `L` だけが大文字。トラック名は大文字。
- 命令と命令の間の空白は無視する。1 つの命令の中には空白を入れられない（例：`c 4` は「`c` と、続く `4`」になりエラー。私の判断）。
- 時間分解能は四分音符 = 96 ティック（spec のとおり）。

### 3.2 トラック名

| 名前 | 用途 |
|---|---|
| `A`〜`P` | メロディ用（spec §4.2） |
| `A1`、`A2`、…（`A`〜`P` に 1 以上の整数） | サブトラック。M3 では、ほかのメロディ用トラックと同じに扱う |
| `R` | ドラム専用 |

- これ以外の名前（例：`Q`、`a`、`A0`）はエラー。
- 1 つのトラックは、同時に 1 音だけを鳴らす（和音はサブトラックに分ける：spec §4.2）。ただし、前の音の余韻（キーオフ後のリリース）と次の音は重なってよい。

### 3.3 命令

| 命令 | 範囲・既定 | 決めたこと |
|---|---|---|
| `c d e f g a b` | — | 直後に `+` または `-`（1 個。私の判断）、音長、付点の順に書ける。`o4` の `c` を MIDI のノート番号 60 とする（私の判断）。ノート番号が 0〜127 を外れたらエラー |
| `r` | — | 休符。音長と付点を書ける |
| 音長 | 1, 2, 4, 8, 16, 32、3 連の 3, 6, 12, 24, 48 | spec のとおり。これ以外の数はエラー |
| `%N` | N は 1 以上の整数 | 音長をティックで直接書く（spec のとおり）。音符・休符の音長の位置に書く（例：`c%36`、`r%12`） |
| `.` | — | 付点。重ねてよい（`c4..` は 96 + 48 + 24）。ティックが整数にならないとエラー（私の判断） |
| `oN` | 0〜8、既定 4 | spec のとおり |
| `<` `>` | — | 1 オクターブ下げる・上げる（spec のとおり）。0〜8 を外れたらエラー |
| `lN` | 音長と同じ数、既定 `l4`（私の判断） | 付点も書ける（例：`l8.`。私の判断） |
| `&` | — | タイ。§3.5 |
| `tN` | 1〜999、小数可、既定 120（私の判断） | 全トラックに効く。§3.6 |
| `@N` | 0〜127、既定 0 | メロディ用トラックだけ。登録されていない番号はエラーにせず、鳴らすときに音源が警告を出す（M2 のまま。解析器は登録済みの番号を知らないため。私の判断） |
| `vN` | 0〜15、既定 12 | 持続中のノートにもその位置から効く（依頼者の決定。M5 で CC7・CC11 の変化を表すため）。持続中のノートの途中に書くには、タイの間に書く（§3.5）。効く対象は `B` と同じく、そのトラックが最後にノートオンしたノート（§3.8）。1 段 3 dB、`v15` を 0 dB、`v0` を無音とする（依頼者の決定。暫定で、試聴で調整してよい） |
| `pN` | 0〜127、既定 64 | 次の音から効く（M2 で決めたとおり） |
| `qN` | 1〜8、既定 8 | ゲートタイム（依頼者の決定）。音長の N/8 のところでキーオフする。§3.7 |
| `B±N` | −1200〜+1200（セント）、既定 0 | ピッチベンド。§3.8 |
| `[ ... ]N` | N は 1〜255 の整数（上限は私の判断） | 繰り返し。入れ子可。**N は省けない**（省いたらエラー。依頼者の決定） |
| `L` | — | ループの開始位置。§3.9 |
| `E` | — | ループの終了位置（spec にない命令。依頼者の決定、名前は私の判断）。省けば曲の終わり。§3.9 |

- 数を取る命令（`o l t @ v p q` と `[ ]` の回数）で数がないものはエラー。
- 範囲外の値はエラー。

### 3.4 ドラムトラック（R）

- 音符の代わりにドラム名（`bd sd ch oh cy lt ht cp`）を書く。音長・付点・`%N` は音符と同じ。ドラム名を 1 文字の命令より優先して照合する（spec のとおり）。ドラム名はドラムの番号（128〜135。M2 設計書 §5）に対応する。
- 使える命令：`r`、`l`、`%`、`.`、`v`、`p`、`q`、`t`、`[ ]`、`L`、`E`。
- 使えない命令（エラー）：音符、`o`、`<`、`>`、`@`、`&`、`B`（私の判断。ドラムは高さを持たず、`noteOff` を無視して鳴り終わるまで鳴るため。`q` は書けるが効き目はない）。

### 3.5 タイ `&`

- `&` は前の音符と次の音符を 1 つの音としてつなぐ。鳴らし直さず、長さを足す。
- `&` の前後の音符が違う高さ（ノート番号で比べる）ならエラー（依頼者の決定）。例：`c4&d4`。
- `&` と次の音符の間には、`B` と `v` だけを書ける（私の判断）。どちらも、持続中のノートの途中で高さ・音量を変えるために要る（§3.3、§3.8）。それ以外の命令を挟んだらエラー。
- `&` の後に音符がない（トラックの終わり、休符、`]` など）ときはエラー。行末の後は、同じトラックの次の行に続けて書ける（§3.1）。`[ ]` の境をまたぐタイ（例：`[c4&]2`）もエラー（私の判断）。

### 3.6 テンポ `t`

- どのトラックに書いてもよく、書いた位置（ティック）から全トラックに効く（spec のとおり。慣例として `A` に書く）。
- 違うトラックで同じティックに違うテンポを書いたらエラー（私の判断）。
- テンポが途中で変わる曲でも、ティックからサンプル時刻への変換はずれを溜めない（各テンポの区切りから時刻を計算し、丸めは音源へ送る時の 1 回だけにする。私の判断）。

### 3.7 ゲートタイム `q`

- 音符（タイでつないだものは全体）の長さ × N / 8 のティックでキーオフする。小数は切り捨て、最小 1 ティック（私の判断）。
- 休符には関係しない。

### 3.8 ピッチベンド `B`

- `B±N` は、そのトラックの高さを N セントずらした状態にする。値は、次に `B` を書くまで持ち越す（`B+0` で戻す。依頼者の決定）。
- 持続中のノートにもその位置から効く（依頼者の決定）。高さはその時点で一度に変わる（滑らかには変えない）。対象は、そのトラックが最後にノートオンしたノート（ノートオフ後のリリース中でも）。次の音は、その時点の値で鳴り始める（私の判断。MIDI のチャンネルのピッチベンドと同じ考え方）。
- つないだ音の途中で変えるには、タイの間に書く（例：`c8&B+50c8`）。高さを滑らかに変えるには、値を少しずつ変えた `B` を `%N` の短い音でつないで並べる（例：`c%6&B+10c%6&B+20c%6`）。M5 の変換ツールは、MIDI のピッチベンドをこの形で書き出す。
- `B` は 1 ティック単位の位置に置ける（`%1` を使えば。テンポ 120 で約 5 ms）。
- 符号は省けない（`B50` はエラー。spec の `B±N` のとおり。私の判断）。

### 3.9 ループ `L` と曲の終わり

- 曲の長さは、いちばん長いトラックの長さとする（依頼者の決定）。短いトラックは、終わってから曲の終わりまで休みになる。
- `L` があれば、ループ終了の位置まで来たら `L` の位置へ戻り、繰り返す。冒頭に `L` を書けば、最初から最後までを繰り返す。`L` がなければ、最後まで鳴らしたら止める（依頼者の決定）。
- ループ終了の位置：`E` を書けばその位置、書かなければ曲の終わり（依頼者の決定。命令の名前 `E` は私の判断）。
- `L` は曲全体で 1 つまで（どのトラックに書いてもよい：spec のとおり）。2 つ以上はエラー。`[ ]` の中の `L` もエラー。`L` がループ終了と同じ位置（繰り返す長さが 0）もエラー（私の判断）。
- `E` も曲全体で 1 つまで、どのトラックに書いてもよい。2 つ以上、`[ ]` の中、`L` がない曲、`L` より前の位置はエラー（私の判断）。
- 戻ったときの状態：各トラックの音色・音量・パン・`q`・ピッチベンドと、テンポは、最初に `L` の位置を通ったときと同じにする（私の判断。MIDI の再生器のコントロールのチェイスと同じ考え方）。この状態は、戻った後にノートオンするノートに効かせる。下の「ループ終了を越えるノート」には `setPitchBend`・`setVolume` を送らない（私の判断）。

#### ループ位置をまたぐノート（依頼者の決定）

- `L` より前にノートオンし、`L` の位置で持続中のノートは、戻ったときに鳴らし直さない（MIDI の再生器で多い扱い）。
- ループ位置をまたいでノートを鳴らしたいとき（弱起など）は、ループ終了の前にノートオンし、音長をループ終了より後まで書く。そのノートは戻った後も、書いた長さ（`q` を掛けたもの）が尽きるまで持続し、そこでノートオフする。例：`L` が 5 小節目の頭、`E` が 13 小節目の頭のとき、12 小節目の 4 拍目の裏でノートオンし、付点 4 分音符の長さを書けば、戻った後の 5 小節目の 1 拍目の終わりまで持続する。
- `E` より後に書けるのは、ループ終了を越えるノートの残りの長さと、休符だけ（私の判断）。`E` の位置かそれより後でノートオンするノートや、`E` より後の命令（`B`・`v` などのタイの間のものを含む）はエラー。その部分は鳴ることがないため。
- 戻った後、そのトラックの `L` の後のノートが、越えてきたノートと重なってもよい（1 つのトラックで 2 つのノートが同時に持続する）。`B`・`v` が効く対象は、§3.8 のとおり最後にノートオンしたノート。
- `E` がない曲では、曲の終わりより後まで書かれたノートはない（曲の終わりはいちばん長いトラックの終わりのため）。曲の終わりの時点で鳴っている音（例：最後の音符の余韻）は切らない。

### 3.10 エラー

- 解析エラーは、行番号・列番号（どちらも 1 から。列は文字単位）・理由（日本語）を付けて返す（spec のとおり）。
- 見つけたエラーはまとめて返す（最初の 1 つで止めない。私の判断）。1 つのエラーの後の続きの読み方（例：次の空白まで飛ばす）は実装に任せる。ただし、同じ原因で大量のエラーを出さないようにする。
- エラーが 1 つでもあれば、M3 の再生器は再生しない（私の判断。トラックごとに無音にする動きは M4）。

## 4. 音源への追加（packages/engine）

| 追加 | 内容 |
|---|---|
| `noteOn` の音量 | 0〜1 の倍率を受け取り、そのボイスの出力に掛ける（既定 1）。`v` から倍率への変換（1 段 3 dB）は sequencer が行う（私の判断。音源を MML に依存させないため） |
| `noteOn` のピッチベンド | 鳴り始めのずれ（セント、−1200〜1200、既定 0） |
| `setPitchBend` | `id`、`cents`、`time`。その音の全オペレーターの周波数を 2^(cents/1200) 倍にする。位相は続けたまま変える。奪われた・鳴り終えた音なら何もしない。ドラムには効かない |
| `setVolume` | `id`、`volume`（0〜1 の倍率）、`time`。持続中のノートの音量を変える。奪われた・鳴り終えた音なら何もしない。`R` トラックにはタイがないので、ドラムには使わない（`R` の `v` は次のドラムから効く。私の判断） |
| 予約の取り消し | 再生器は少し先の発音をサンプル時刻付きで送るため、停止したときに送り済みの `noteOn`・`noteOff` が残る。`noteOff` だけが届かず音が鳴り続けることがないよう、「指定した ID の、まだ処理していないイベントを捨て、鳴っていればキーオフする」メッセージを足す（形は計画で決める。私の判断） |

- 音量の変数名・暫定値（1 段の dB）は `README.md` の暫定値の一覧に加える。
- 引数の検査は M2 と同じく `RangeError` を投げる。
- メッセージの型（`messages.ts`）、`processor.ts`、`FmEngine`（`index.ts`）をこれに合わせる。`processor.ts` は薄く保つ（CLAUDE.md）。

## 5. 試聴ページ（demo）

### 5.1 MML の欄

M2 の画面に、次を足す。

- MML を書く欄（複数行）。最初は §5.2 の曲が入っている。
- 再生・停止のボタン。再生中に再生を押したら、最初から鳴らし直す（私の判断）。
- エラーの一覧（行番号・列番号・理由）。エラーがあれば再生しない。
- 音源の警告（例：登録されていない音色）を表示する（M2 の警告の欄を使ってよい）。
- 音色：同梱の GM 音色（`voices/ymf825/gm.json` の 16 種）を GM の番号に、ドラム 8 種を 128〜135 に登録する。
- 鍵盤は今、選んだ音色を `program` 0 に登録し直して鳴らしている（`demo/main.ts` の `KEYBOARD_PROGRAM`）。0 は GM のピアノの番号で MML の `@0` とぶつかるので、鍵盤用の番号を MML と重ならないものに変える（番号は計画で決める）。
- 再生のしかた：M2 のリズムと同じく、メインスレッドから少し先の発音をサンプル時刻付きで送る（依頼者の決定）。タブが裏に回るなどしてタイマーが遅れたときは、逃した音をまとめて鳴らさず、今の時刻から先を鳴らす（M2 のリズムと同じ考え方。私の判断）。

### 5.2 手書きの曲

- 設計者が 1 曲書く（依頼者の決定）。長さは 30 秒ほどで、イントロの後に `L` を置き、そこから繰り返す。
- 入れるもの：メロディ・ベース・和音（サブトラック）・ドラムの複数トラック、`v`（タイの途中で変える箇所を含む）、`p`、`B`（タイの途中で変える箇所を含む）、`q`、`[ ]` の入れ子、途中のテンポ変更、`E` とループ終了を越える弱起のノート（私の判断。§1.1 の確認 1・4 のため）。音色は `gm.json` にある番号だけを使う。
- **既存の曲の旋律を写さず、新しく作る**（私の判断。権利面のため）。
- 置き場：`demo/songs/` に `.mml` として置き、試聴ページが読み込む（私の判断）。どの小節で何を使っているかを、曲のコメントか画面の説明に書く。

## 6. パッケージの構成（目安）

| ファイル | 内容 |
|---|---|
| `packages/sequencer/src/parser.ts` | MML → 曲（トラックごとのイベント列、ループ位置、テンポの列）とエラー |
| `packages/sequencer/src/timing.ts` | ティック → 秒（テンポの列から） |
| `packages/sequencer/src/player.ts` | 曲を、指定した時刻から先読みして音源へ送る。ループ。停止 |
| `packages/sequencer/src/index.ts` | 公開する型と関数 |

- 依存の向きは `sequencer → engine`（spec §1）。再生器は音源を直接 import せず、`noteOn`・`noteOff`・`setPitchBend`・取り消しを持つ型を受け取る形にして、Vitest で偽の音源を渡して確かめられるようにする（私の判断）。
- 解析器と時刻の計算は、ブラウザーにも Worklet にも依存しない（M5 の変換ツールが Node から往復検証に使うため：spec §1）。

## 7. 確かめ方（実装側）

- Vitest：
  - 解析：各命令（§3.3）の正しい書き方と、範囲外・数の書き忘れ・使えない場所での使用のエラー。行番号・列番号が正しいこと。
  - 音長：全音長のティック、付点（重ねたものを含む）、`%N`、`l`、3 連。
  - タイ：長さが足されること、違う高さでエラー、間に `B` を挟めること、それ以外を挟むとエラー。
  - 繰り返し：入れ子、N の省略でエラー、`]` と `[` の対応の誤り。
  - ドラムトラック：ドラム名の優先（`lt` をロータムと読む）、使えない命令のエラー。
  - テンポ：途中で変わる曲の時刻、トラックをまたぐテンポ、同じティックの食い違いでエラー。
  - ループ：曲の長さ、`L` の位置へ戻ること、戻ったときの状態、`L` がなければ止まること、`L` が 2 つ・`[ ]` の中・長さ 0 でエラー。
  - ループ位置をまたぐノート：`L` の前から持続中のノートを戻った後に鳴らし直さないこと、`E` を越えるノートが戻った後も書いた長さで持続しノートオフされること、`E` の各エラー（2 つ、`[ ]` の中、`L` がない、`L` より前、`E` の後のノートオンや命令）。
  - `q`：キーオフの位置。
  - 再生器：偽の音源に届くイベントの時刻と順番、先読みの範囲、遅れたときに逃した音をまとめて送らないこと、停止で予約が取り消されること。
  - 音源：音量の倍率、`setPitchBend` で周波数が変わる・奪われた ID は何もしない、取り消し。
  - §5.2 の曲がエラーなく解析できること。
- `npm run check:browser`（ヘッドレス Chromium）：M2 までの確認に加え、§5.2 の曲を再生すると音が出てエラーが起きないこと、停止すると無音に戻ること、間違えた MML でエラーが表示されること。
- 完了の報告の前に `npm test`、`npm run build`、`npm run check:browser` を通す（CLAUDE.md）。
