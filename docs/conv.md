# SMF → MML 変換（conv）

DAW（Domino など）で作った SMF を、`FmAudio` でそのまま鳴らせる MML に変換する道具の文書。製品仕様は `docs/spec.md` §6、MML の文法は `docs/mml.md`。実装は `packages/conv`。

出力した MML は手で直さずに使う想定なので、読みやすさより SMF への忠実さを優先している（`[ ]` でのまとめや `l` による音長の省略はしない）。

## 使い方

```
npm run conv -- song.mid -o song.mml [--quantize 32] [--report]
```

Node 22.18 以上が必要（`.ts` を Node で直接実行する）。

| 指定 | 内容 |
|---|---|
| `song.mid` | 入力の SMF。1 つだけ。相対パスは `npm run` を実行した場所から解く |
| `-o song.mml` | 出力先。省くと標準出力に MML を書く |
| `--quantize N` | 量子化の単位を N 分音符にする。4・8・16・32・64 のどれか。既定は 32 |
| `--report` | 捨てたイベントの種類と件数、チャンネルとトラック名の対応、ループの位置を標準エラーに出す |

- 警告は標準エラーに出す。エラーがあれば MML を書かず、終了コードを 0 以外にする。
- 変換した MML は、書く前に必ず `parseMml` で解析し直す。エラーが 1 件でもあれば、MML を書かず、`parseMml` のエラー（先頭の 3 件）を出して止まる。
- 読める SMF はフォーマット 0 と 1。フォーマット 2 と、時間の単位が SMPTE のものはエラー。
- `conv` は `packages/sequencer` の `parseMml` などだけを使い、ゲームへはコピーしない（`npm run export:runtime` の対象外）。

## Domino でのループの入れ方

SMF のマーカー（メタイベント 0x06）で示す。マーカーの文字を `loop`・`loopend` にする（大文字・小文字は区別しない。前後の空白は無視する）。

| マーカー | MML |
|---|---|
| `loop` | `L`（ループの頭） |
| `loopend` | `E`（ループの終わり） |

- マーカーを入れなければ、曲の頭から、最後のノートオフを含む小節の終わり（次の小節線）までをループさせる。小節は SMF の拍子から求め、拍子がなければ 4/4。
- `loop` と `loopend` は両方入れるか、両方入れないかにする。片方だけ、`loopend` が `loop` より前か同じ位置、どちらかが 2 つ以上、のときはエラー。
- `loopend` の位置かそれより後のノートオンと変化（音量・ベンド・テンポ・パン・音色）は、鳴ることがないので書かず、件数を警告に出す。`loopend` より前にノートオンして `loopend` を越えて続くノートは、そのまま越えて書く（ループ後も持続する。`docs/mml.md`）。
- ノートが 1 つもない SMF はエラー。
- 変換した曲はすべてループする。ループしない曲は作れない。

## 変換の規則

### トラックの割り当て

- チャンネル 1〜16 を `A`〜`P` に割り当てる。チャンネル 10 は `R`（ドラム）。ノートのないチャンネルはトラックを作らない。
- テンポ・`L`・`E` は、休符だけの指揮用トラック `J` に書く。タイの間には `B`・`v` しか書けず、ノートのあるトラックに書くと持続中のノートの途中のテンポ変更が書けないため。`J` はチャンネル 10 の位置の文字で、ノートのトラックには使われない。
- フォーマット 1 では全トラックのイベントを時刻順に合わせ、MIDI チャンネルごとに扱う。同じチャンネルのイベントが複数の SMF トラックにあってもよい。
- サブトラックと `R`、`J` を含めてトラックが 30 を超えたらエラー。エラーの文にチャンネルごとのトラック数を出す。

### 和音・同時打ち

- 1 つのチャンネルで同時に 2 音以上が鳴る区間があれば、そのチャンネルをサブトラック（`A1`、`A2`、…）に分ける。和音のないチャンネルは `A` のまま。サブトラックの数は、そのチャンネルの同時発音数の最大に等しい。
- 同じ時刻に始まる音は高い音から順に、空いている最初のサブトラックに入れる（持続中のノートは途中で別のサブトラックへ移せないため）。
- 音色・パン・音量・ピッチベンドは、そのチャンネルのすべてのサブトラックに書く。
- ドラムで同じ時刻に 2 つ以上を打つ（バスドラムとハイハットなど）ときも、同じように `R1`、`R2`、… に分ける。同時打ちのない曲は `R` のまま。同じ時刻の打撃は `bd sd ch oh cy lt ht cp` の順（`DRUM_PROGRAMS` の順）に `R1` から詰める。
- 同時に鳴るノートが 16 を超えた箇所は、小節・拍の位置を付けて警告する。自動では間引かない。メロディは `on ≤ t < off`、ドラムは打撃の時刻だけを数える。

### 量子化と 3 連符

- 既定は 32 分音符（12 ティック）単位。`--quantize` で 4・8・16・32・64 分音符を選べる。MML の時間分解能は四分音符 = 96 ティック。
- 3 連符は、単位の 2/3（既定で 8 ティック）の格子にそろえる。拍（四分音符）ごとに、ノートオンとノートオフのずれの合計が、普通の格子と 3 連の格子のどちらで小さいかを比べ、3 連のほうが小さい拍だけ 3 連にする。
- 量子化は、ノート・変化・テンポ・マーカー・拍子の位置にかける。
- 音長は `1 2 4 8 16 32`、3 連の `3 6 12 24 48`、付点（1 つまで）でちょうど表せるときはそれを使い、表せないときは `%N`（ティック数）で書く。どちらでも鳴る音は同じ。
- ノートの間のすき間は休符で埋める。各トラックの最後は休符でそろえない（曲の長さはいちばん長いトラックで決まる）。`J` だけは `E` まで休符で埋める。

### 音量

- ノートの音量は、チャンネルボリューム（コントロールチェンジ 7 番）× エクスプレッション（11 番）× ノートのベロシティで決め、`v` の 16 段階に丸める。
- 換算：3 つの値（0〜127）をそれぞれ 40 × log10(値 / 127) dB とみなして足し、`v` = 15 + round(合計 dB / 3)。1 段 3 dB で、`v15` が 0 dB。3 つのどれかが 0 なら `v0`、それ以外で 1 を下回れば `v1`。
- SMF に値がないときの初期値は、ボリューム 100、エクスプレッション 127（GM の初期値）。
- ノートの途中でボリュームかエクスプレッションが変わったら、その位置にタイ `&` で分けて `v` を書く。値が変わらない `v` は書かない。同じ位置（量子化の後）の変化は最後の値だけを書く。
- ドラムも同じ換算で、ドラムごとに `v` を書く。

### ピッチベンド

- `B` のセントに換える。ベンド幅は既定で ±2 半音。RPN 0（ピッチベンド・センシティビティ）があれば、そのチャンネルの以降のベンドに反映する（データエントリーのコントロールチェンジ 6 番が半音、38 番がセント）。
- 換えた値（四捨五入したセント）が ±1200 を超えたらエラー（位置つき）。
- 同じ位置の変化は最後の値だけを書き、値が変わらないものは書かない。休符の間のベンドも、位置に `B` を書く。

### パン・音色・テンポ

- パン（コントロールチェンジ 10 番）は `p`、プログラムチェンジは `@`（GM の番号のまま）に換える。どちらも次の音から効くので、次のノートの直前に書く。
- テンポは `t` に換える。`J` に書く。テンポの指定が SMF の頭（tick 0）になければ、120 から始める。BPM は小数第 2 位まで。1〜999 を外れたらエラー（位置つき）。

### ドラム

- チャンネル 10 のノートを、次の割り当てでドラム名に換える（`docs/spec.md` §6.6）。

  | ドラム名 | GM のノート番号 |
  |---|---|
  | `bd` | 35, 36 |
  | `sd` | 38, 40 |
  | `cp` | 37, 39 |
  | `ch` | 42, 44 |
  | `oh` | 46 |
  | `cy` | 49, 51, 52, 55, 57, 59 |
  | `lt` | 41, 43, 45 |
  | `ht` | 47, 48, 50 |

- 割り当てのない番号は捨て、番号ごとに最初の位置と件数を警告する。
- ドラムは鳴り始めたら鳴り終わるまで鳴る（`docs/mml.md`）ので、SMF のノートオフの位置は見ない。音長は次の打撃まで（最後の打撃は `E` まで）。

## 警告とエラー

警告は「12 小節 3 拍：…」の形で、位置の順に標準エラーへ出る。

### 警告

| 内容 | 意味 |
|---|---|
| チャンネル N のノート M にノートオフがありません。曲の最後で終えます | ノートオフのないノート。SMF の最後のイベントの位置で終える |
| チャンネル N のノート M は量子化で長さが 0 になるため、単位 1 つ分に延ばします | 量子化で長さ 0 になったメロディのノート |
| ドラムのノート N は割り当てがないため捨てます（K 件） | 上の表にないドラムの番号 |
| 同時に鳴るノートが N 個になり、16 を超えます | 16 を超える状態に入るたびに 1 件（一度 16 以下に戻って再び超えれば、また出る） |
| ループ終了（loopend）より後のノート N 件・変化 M 件を捨てました | `loopend` 以降のノートオンと変化 |

### エラー

変換を止める。MML は書かない。

- SMF が読めない：`MThd` がない、途中で切れている、フォーマット 2、SMPTE 形式、分解能 0、未対応のステータスバイト。
- ノートがない。
- マーカーの組み合わせが正しくない（上の「Domino でのループの入れ方」）。
- トラックが 30 を超える。
- ノート番号が 12 未満か 120 以上（`o0`〜`o8` で書けない。ドラムは番号を見ないので対象外）。
- ピッチベンドが ±1200 セントを超える。
- テンポが 1〜999 を外れる。
- 変換した MML を `parseMml` が受け付けない（1 トラックのイベントの上限 10 万など）。

### `--report`

標準エラーに次を出す。

- 捨てたイベントの種類と件数（コントロールチェンジの番号ごと、メタイベントの種類ごと、システムエクスクルーシブ、チャンネルプレッシャーなど）。
- チャンネルとトラック名の対応（和音で分けた数がわかる）。
- ループの位置。tick（四分音符 = 96）で、マーカーから取ったか、マーカーがないので曲全体かも出す。

## 実装で決めたこと

設計書で決まっていなかった挙動を、実装が決めたもの。依頼者に確認する。

- ノートオフのないノートは、SMF の最後のイベントの位置で終え、警告する。同じチャンネル・同じ音のノートオンが、前のノートのノートオフより先に来たら、前のノートをその時刻で終える。対応するノートオンのないノートオフは無視する。ベロシティ 0 のノートオンはノートオフとして扱う。
- 長さが 0 以下のノート（同じ位置のノートオンとノートオフ、ノートオフのないノートが SMF の最後のイベントの位置にある場合）は、警告なしに捨てる。
- 量子化で長さが 0 になったノートは、その位置の格子の単位 1 つ分に延ばして警告する。量子化で同じ音が重なったら、前のノートを次のノートオンで終える（警告なし。そのとき前のノートの長さが 0 になれば捨てる）。
- ノート番号が 12 未満・120 以上はエラー。BPM は小数第 2 位まで。同じ時刻の同じドラム名は、ベロシティの大きいほうを 1 つだけ残す。
- 既定の 32 分単位では 3 連の格子（8 ティック）のほうが普通の格子（12 ティック）より細かい。そのため、手弾きで 16 分音符の位置から大きくずれた音（MML の分解能で 5 ティック以上）は、3 連に化けることがある。Domino の打ち込みでは起きない。起きたときは `--quantize` を変えるか、DAW で位置をそろえる。
- チャンネル 10 のプログラムチェンジとピッチベンドは `R` に書けないため捨て、`--report` に出す。`--report` のループの位置は tick 表示。
- 拍子が小節の途中で変わったときは、その位置から新しい拍子の小節が始まるとみなす（`loop` なしのときの曲の終わりに影響する）。
- 同じチャンネルのコントロール（ボリューム・エクスプレッション・パン・音色・ベンド）は、SMF のトラックの区別なくチャンネルごとに扱う。
